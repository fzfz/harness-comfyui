# 实验工作台交互原型

## 1. 打开原型

1. 使用浏览器打开 [index.html](./index.html)。页面使用内置脚本与矢量图，无需安装依赖。

## 2. 体验路径

1. 功能配置：打开“配置中心”，分别设置生成提示词、运行任务、分析结果和持续实验的默认预设。点击“编辑”，选择 Agent 提供商、模型、推理等级和 Skill，再填写执行要求。执行要求保留 `{{task_id}}`，供 Agent 按 ID 读取和提交。点击“恢复默认要求”可使用所选功能的执行步骤。
2. 生成提示词：返回工作台，填写右栏“原始需求”，点击“生成提示词”。在弹窗填写任务要求并提交。提交后提示显示任务入口。提示词回填后，选齐生成资源，再点击“运行任务”。两个功能分别使用各自的默认绑定。
3. 局部委托：点击“改写提示词”或“建议参数”，填写任务要求。任务完成后，查看对应字段；点击“推荐资源”后，可查看并采用资源候选。
4. 输入冲突：发起改写任务后，立即手动修改提示词。任务完成后，查看保留的候选产物，再选择采用或从产物创建分支。
5. 任务继续：在任务卡中点击“中断任务”，刷新后点击“继续任务”。原始需求为空时，任务卡提供补充需求入口。
6. 原图与结果分析：点击结果图可打开原图弹窗，关闭后保留浏览位置。选择运行卡片，打开“记录评价与经验”，点击弹窗内的“分析结果”。观察与评价回填后可继续编辑，点击“保存”写入该 Run。点击“比较运行”后，通过卡片选择比较对象。
7. 资源选择：打开“资源”，按分类、底模或生成模型筛选。选择模板和 LoRA 后，在右栏核对所选资源并调整 LoRA 权重。
8. 模型更换：在右栏的“生成模型”下点击“更换”。选择另一底模的模型，确认移除不兼容资源后，再选择适用模板。
9. 分支继承：选择运行卡片 → “从此运行创建分支” → 填写名称与需求。子分支继承所选 Run 的运行输入，运行记录按分支分别展示。
10. 持续实验：选择“持续实验”，设置最多运行次数。点击“开始实验”，查看每轮运行输入与结果。各轮可使用不同模型、模板、LoRA、参考图路径和参数；选择运行卡片可查看当轮输入。
11. 实验接续：暂停实验 → 刷新页面 → 继续实验。结束实验后，已提交 Run 继续完成，后续轮次停止提交。
12. 失败处理：点击“ANIMA3 复验”的失败卡片，再点击“诊断失败”或“重试任务”。重试会新增卡片，原失败卡片继续保留。
13. 经验复用：打开“记录评价与经验”，在弹窗中点击“整理经验”。编辑回填的标题、条件和结论，点击“保存”，再打开经验页。点击“复用经验”，选择目标底模，再创建分支。
14. 工作切换：新建工作 → 配置主分支 → 运行 → 切回原工作，查看各自的分支、任务和运行。
15. 本次预设：在运行区选择“本次预设”，再点击“运行任务”。本次运行使用所选预设，下次运行使用配置中心的默认预设。
16. 实验预设：以“ComfyUI-完整工作流”开始实验，暂停后到配置中心修改持续实验的默认预设，再继续实验。各轮仍使用启动时的绑定。
17. 自定义功能：添加“强化玻璃反射”，选择“改写提示词”类型，填写预设、Skill 与执行要求。返回工作台，从提示词区域发起该功能，查看任务与返回产物。移除功能后，历史任务继续保留。

18. 请求追溯：发起 Agent 功能后，打开任务卡的“查看任务详情”，查看当次完整请求。再修改配置中心的执行要求，已有任务仍显示创建时保存的内容。
19. 添加工作区：在顶栏点击“添加工作区”，填写名称与项目目录。进入空工作区后，新建工作并填写目标。刷新页面后，再从工作区列表打开该工作。
20. 工作区切换：在“场景创作”中运行任务，再切换至“模型评测”。“模型评测”显示该工作区的工作和功能配置；切回“场景创作”后，可查看运行结果与草稿。
21. 参数追溯：选择 ComfyUI 实例、模型和模板，发起任务后展开“查看任务详情”。执行请求保存配置中心的执行要求和任务 ID；输入 JSON 保存用户需求与生成参数。

## 4. 验证范围与依据

1. 当前交付为浏览器交互原型。自动返回使用固定样例；原型可验证产物格式校验与字段回填，合同见设计第 5.3.1 节。生成运行与图像使用演示数据。工作区、工作、分支、配置、任务、运行、评价草稿和经验保存在浏览器本地。真实 Agent 的任务理解与工具调用仍需接入验收。
2. 交互布局参考 NovelAIPromptStudio 固定提交 `0851e73d1e86e75783030c0062c887c0dc991035` 提供的[工作台截图](https://github.com/LBEILC/NovelAIPromptStudio/blob/0851e73d1e86e75783030c0062c887c0dc991035/doc/screenshots/readme-workbench.webp)与[分支图截图](https://github.com/LBEILC/NovelAIPromptStudio/blob/0851e73d1e86e75783030c0062c887c0dc991035/doc/screenshots/readme-branchmap.webp)。
3. 目录交互依据当前官方 Desktop 的“插入 ComfyUI 上下文”弹窗及 [WorkbenchDockSession](../../src/client/workbench/native-surfaces.tsx)。整合后的资源归属见设计第 5.6 节。
4. 预设名称、主子 Agent 与技能集样例依据[现状调研](../../docs/research/harness-comfyui-workbench-current.md)第 8 节。原型使用静态名册；功能绑定初始选择内置预设；Skill 选项使用样例集合。真实名册、装配状态、能力校验与会话内 Skill 由设计第 5.3 节的官方接口提供，须在隔离 Desktop 验收。
5. 目录选择、存在性检查和官方 Workspace 注册属于产品接入范围，依据见设计第 5.2.1 节。初始页面提供两个工作区样例，用户可继续添加。
6. 请求与产物使用结构化字段；资源 ID 和模板参数描述使用本地样例。实际 MCP、会话和 CLI 格式见[输入合同调研](../../docs/research/harness-agent-input-contract.md)。工具实施范围见设计方案第 5.3.1 节。浏览器中的读取、帮助、提交和会话归属校验由本地函数模拟。

7. Agent 模型名册取自本机 Desktop Profile 的 LAN GPT 与 OpenCode Go，包含 4 个模型样例。来源为 `/Users/fzfz/.dsh/profiles/desktop/cordis.patch.yml` 的名称与 `reasoningEfforts` 字段，读取日期为 2026-11-07。字段合同见输入调研第 2.1 节；模型调用与选择回执由原型模拟。
