# 生成子任务提示词与完成条件

```text
加载 comfyui-generate，仅执行以下已准备的小批次。
template_id：<ID>
instance_id：<用户已指定的实例ID；未指定时明确写未指定，由原生 Skill 查询取得>
model_id：<ID>
LoRA ID有序列表：<列表>
完整 Prompt Builder 结果 JSON：<原生JSON原文>
图片数量和尺寸：<本轮唯一候选的图数、明确尺寸要求>
逐图 Seed 计划：<每张图的明确整数，或本轮授权取得新Seed的对应图片；复用历史Seed时附完整Run对应关系>
本次 Agent 任务允许写入的产物目录：<目录，不作为生成 Skill 或 CLI 参数传入>
逐图请求、提交状态与回执保存路径：<每张图的具体文件路径>
本阶段可用提交额度：<主流程预留的调用次数>
下列文件保存要求由你作为执行 Agent 完成；不要修改被加载的 Skill 文件或向现有 CLI 添加参数。

按该 Skill 完成参数核对和请求检查。首次提交前，保存全部计划图片的完整请求及 prepared 状态。每次调用前检查剩余额度，再保存 submitting 状态并占用一次额度；得到回执后立即保存 Run ID 或明确错误。额度包含本阶段的重试调用，不能超额。若输入不足以构造完整请求，记录具体缺项，返回 needs_input，本批不提交。
按计划逐图提交，保留图片序号与 Run 的对应关系。遇到无法确认是否已受理的调用，保存 unknown，停止本批后续调用，未调用项保留 prepared 并注明停止原因，不重复该次提交。不要修改 Prompt、发起下一候选、等待整轮生成或读取图片。
明确失败时按原生 Skill 的错误合同处理；合同允许重试或继续且额度足够时才调用，要求停止或额度不足时将剩余项保留 prepared 并注明原因。已受理请求也要在部分失败时保留。恢复时先读取逐图记录；accepted 不重复提交，unknown 交查询子任务核对，无法确认时由主 Agent 转交用户决定，只有确定未提交或未受理的项目才可在新委派中按剩余额度处理。结果按序列出每张图的请求路径、提交状态、Run ID或错误，保存 result.json 后结束。
```

完成条件：进入提交处理的批次，每个计划项都有完整请求及明确提交状态；因输入缺失而未进入提交处理的批次，记录缺项。全部已受理返回 completed；存在 unknown（包括全部 unknown）返回 partial；没有 unknown 但只有部分图片已受理也返回 partial；没有已受理且有明确提交失败返回 failed；其余仅因输入或额度缺失未提交的情况返回 needs_input。这些状态都不表示图像生成完成；查询子 Agent 查询并保存实际 arguments、Actual Workflow 和媒体结果；主 Agent 只对已取得可读图片的项目派发观察任务。
