# 构图子任务提示词与完成条件

```text
读取 <composition-design.md的实际路径>，按其流程理解下列人物和片段，提出画面设计。
原始材料及来源：<故事、人设、相关言行或材料文件路径>
用户针对成图的明确要求：<用途、交付镜头、锁定条件；没有的项目写未指定>
用户已确认的理解或构图：<原文及目标版本；尚未确认时明确写未确认>
当前需要解决的问题：<首次设计，或用户指出的具体理解分歧>
任务设置：<交付图数、复验口径、预算和允许试验范围>

先说明人物平时重视什么、如何应对他人、片段经历为什么会触动这个人物，以及当下意图、阻碍、内心与外在表现。区分材料事实、心理推导与创作选择。
从连续事件中选择一个值得画出的瞬间，推导观者首先注意什么、随后理解什么和感受到什么。核心表达由理解产生，不要求原故事直接写出。
为目标选择具体人物表现、关系、空间、服装或道具；逐项说明表达作用和可替代程度。原故事没有提供但画面需要的内容可以设计；与核心表达无关或有干扰的细节可以提出省略方案。
分别设计主体的位置与姿态、观者注意画面元素的先后顺序、人物与其他人物或物体的接触关系、取景范围、视觉焦点、遮挡关系、光源方向与光质、主体受光及环境明暗。分别确定各对象与镜头的距离和成图中的清晰程度；明确实际照明设计，不只填写场所名称。
将设计写入 <design.json>：材料依据、人物理解、所选瞬间、核心目标、氛围、各镜头构图、要素取舍、必需项与可见判据、偏好项、待确认分歧。
有用户报告的既有图片问题时，按构图方法的首轮对照章节保存 first_trial，将单一假设、固定项、采用或回退判据及缺少的基线材料一并写进确认稿。每个镜头的 lighting 数组按 light 定义逐光源填写来源、位置与方向、光质、受光部位、相对明暗；确认稿完整展示每个光源的这五项内容。
返回可供主流程展示的确认稿。存在会改变表达方向的分歧时，给出有依据的解释及其画面差异，不要求用户代你列核心要素。完成设计后结束，不生成 Prompt 或图片。
```

完成条件：每个核心要素都能说明其表达作用，主体、空间、焦点和照明各有明确决定，判据包含整体人物表达，构图稿可供用户确认。子任务产出 completed 只代表设计完成，不代表用户已确认。
