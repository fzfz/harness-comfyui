# 确定任务与调度边界

你是本任务的主 Agent，只负责阶段调度、用户确认、预算分配和 `task.json`。业务子 Agent 负责构图、Prompt、生成、Run 查询、读图、比较及归档。使用前台 `subagent` 工具，每次只派一个当前阶段，收到结果后再派发依赖阶段。子 Agent 不派发其他 Agent。

检查 `subagent`、shell 和 `skill` 是否可用。缺少 `subagent` 时，请用户切换到“ComfyUI迭代预设”并暂停；缺少 shell 或 `skill` 时，向用户说明缺少的工具并暂停。一次性 Prompt、生成或读图请求直接加载对应现有 Skill并结束本 Skill 流程。

首次新建或恢复任务，完整读取 `references/records.md`，按该文读取 `assets/record-contract.json` 中任务、配置和阶段结果的对应定义。新建时读取 `assets/defaults.json`，用用户已指定的值覆盖对应配置，确定任务目录。恢复时读取任务状态和阶段摘要，派查询子任务核对未完成项目。保留已有 Run，恢复不等于重新生成。

# 用表达目标约束每轮工作

- 故事和人设用于理解人物、经历与关系。构图子 Agent 先推导观者应理解什么、感受到什么，再提出核心要素供用户确认。
- 按表达作用选择画面元素。只有用户锁定项和核心表达不可随意改变，故事出现的服饰、道具、场所不自动成为成图必需项。
- 构图子 Agent 分别设计主体的位置与姿态、人物与其他人物或物体的接触关系、视觉焦点和光线。根据核心表达确定视觉焦点，不因某个对象更靠近镜头就将其设为焦点；明确光源方向和照明范围，不只填写场所名称。
- 候选试验每轮检验一个假设，保存完整改动和对照；建立基线及复验无需编造改动假设。
- 同一幅图的整体表达与全部适用必需项共同成立，才算图片达标；配方稳定性和用户采用另行判断。

# 按阶段派发任务

首次派发某阶段前，读取 `references/stage-prompts.md` 对应章节和共同委派格式，将模板占位符替换为实际输入。只给子 Agent 本阶段需要的方法文档、材料和允许写入路径。

| 当前条件 | 派发任务与后续动作 |
|---|---|
| 新建任务或用户改变核心目标 | 派构图子 Agent，要求完整读取 `references/composition-design.md`。收到设计后，读取 design.json 中的 confirmation_draft 并完整转交用户，保留其中全部照明决定、必需判据及采用和回退条件，不用条目数量代替内容。保存真实确认原文及设计版本引用。未经确认不派生成 |
| 构图已确认且生成配置未核实或已改变 | 派配置子 Agent 加载 `comfyui-generate` 的查询分支。用实际模型结果的 `skill_name` 指定 Builder；为空或 Skill 不可用时报告缺项并暂停 |
| 建立基线或已有获准的候选假设 | 派 Prompt 子 Agent 加载指定 Builder。随后派比较子 Agent检查构图和改动范围；通过后进入生成，有冲突时退回 Prompt 阶段 |
| Prompt 检查通过且额度足够 | 预留本阶段额度，派生成子 Agent 加载 `comfyui-generate`，保存请求后逐图提交。收到 Run ID 只表示受理，继续派查询任务 |
| 有待查询 Run 或中断阶段 | 派查询子 Agent，要求首次调用前完整读取 `references/run-query-cli.md`。只对取得图片的项目派观察；无图片时按查询结果等待或报告问题，不重新生成；达到该阶段查询上限后保存 waiting 并结束当前轮询，用户继续时再查询 |
| 图片可读 | 派观察子 Agent 加载 `local-image-reader`，保存逐图原始观察。首次观察只给中性问题，不给原始 Prompt、故事解释或预期成功结论 |
| 已有观察或诊断结果 | 派比较子 Agent，要求完整读取 `references/iteration-method.md`，保存比较、下一步及其依据。按返回建议派二次观察、诊断、下一候选或复验；详细业务判断留在子任务 |
| 重复问题需进一步诊断 | 派诊断子 Agent 加载 `comfyui-image-review`；返回建议交比较子任务选择一个待检验假设，不能直接提交整份改写 |
| 比较建议复验 | 按冻结配置与复验计划分别派生成、查询、观察和比较任务；复验图数及新 Seed 来源不明确时先补齐计划 |
| 达成交付条件或停止迭代 | 将推荐图片路径与结论提交用户确认，或沿用明确的自主选图授权；派归档子 Agent写最终文件。未完成任务也归档，保留具体停止原因 |

# 处理返回、额度和停止条件

子任务返回 `result.json` 路径、状态和短结论。读取其中的阶段 ID、产物引用、问题、额度和下一步；完整 Workflow、Prompt、观察及轮次分析保留在文件中。业务证据不足时退回相应子任务补充，不在主会话重做业务分析。

`completed` 仍需具备该阶段要求的产物。`needs_input` 的现有材料由你补传，需要用户决定的项目转交用户；`failed` 只有在原因消除且原执行结束后才能以新阶段重试；`partial` 保留已完成项目，按未完成项分别调度，已接受 Run 不重发。

生成子任务返回的 `consumed` 包含 `reserved_unknown`，两者不相加扣减。中断后在查询子任务核对完成前保留阶段预留额度；确认未调用的部分才能释放。unknown 请求保持额度占用，无法查明是否受理时转交用户决定。

预算耗尽、没有新的可检验假设或当前方向达到停滞上限时，停止对应生成并归档。用户修改锁定条件或核心目标时返回构图确认；只在已确认试验范围内调整表现方式时继续，不重复请求同一授权。

归档完成后返回最终图片、`selection.json` 和 `配方.md` 的实际路径，以及复验状态、用户采用状态或未完成原因。
