# Character Portrait Prompt Designer

## 查询历史 Generation Run

1. 当前立绘提示词任务需要读取、核对或复用历史生成参数或 Actual Workflow 时，Skill 执行者使用用户提供的 `run_id` 查询。
2. 本分支首次使用受管 CLI 时，Skill 执行者通过受管前台 shell Tool Call 读取根帮助：

   ```sh
   ELECTRON_RUN_AS_NODE=1 "$DSH_HARNESS_COMFYUI_NODE_EXECUTABLE" --expose-internals "$DSH_HARNESS_COMFYUI_CLI" --help
   ```

3. 查询前，Skill 执行者读取命令帮助，再按帮助执行查询：

   ```sh
   ELECTRON_RUN_AS_NODE=1 "$DSH_HARNESS_COMFYUI_NODE_EXECUTABLE" --expose-internals "$DSH_HARNESS_COMFYUI_CLI" generation run-inputs --help
   ```

4. 同一会话中，Skill 执行者可复用仍在上下文中的帮助。压缩后缺少操作依据时，重新读取本节或对应帮助。
5. Skill 执行者按 `runs[]` 顺序报告每个 `run_id` 的查询结果。单项查询失败时，继续处理其余结果。

## 立绘设计产物

1. Skill 执行者为指定书籍或角色卡项目中的人物生成以下两类文档：

   1. **外观基准文档**：使用 `{character_name}_外观与立绘提示词.md` 保存稳定外貌。按已读取材料支持的章节或剧情阶段记录变化。
   2. **独立立绘提示词**：为本次要求的每个场景、事件或开场生成自包含的自然语言画面说明。

2. 每个提示词都必须独立完整，不能依赖“人物名”或“另见人物设定”来补全形象。

3. 本 Skill 的立绘提示词必须写成一段连贯的完整画面说明。来源、阶段和设计补充写在正文以外。

4. **生成每张画面提示词前，必须先建立/读取该人物的外观基准文档；然后根据当前场景所属剧情阶段，从外观基准中选取本阶段已成立的特征，自然融入这段画面描述。不得把外观基准整段照抄进每个提示词。**

## 文生图可理解性：只写画面内可见信息

1. Skill 执行者按以下规则描述画面内容：

   1. **人物称呼**：不得写“主人物”“女主”“她叫某某”等抽象/命名，也不得写任何具体人物名/昵称/关系称谓（如“林茜”“杨桃子”“王授军”“黑哥”“丈夫”）。所有角色必须用“年龄/年龄段 + 性别 + 体型/穿着/外貌特征”来指代，例如“一个三十岁左右的中国女性”“一个四十多岁、身高不足一米六、半秃、皮肤皱缩的瘦小男人”。
   2. **剧情/阶段说明**：不得写“这是角色成为某花名之前”“此时尚未驯化”等。如果阶段有视觉后果，直接写成可见状态，例如“脖颈光洁，穿着素净的学生装，神情青涩”。
   3. **地点/专名**：不得写“某山庄”“某村”“某温泉馆”等专名。要写具体视觉环境，例如“近郊高档别墅：铁门、石墙、车道、草坪、玻璃门、石板台阶”“乡村旧院：土墙、旧木门、泥地、昏暗门灯”。
   4. **其他不可画信息**：心理动机、过去/未来、旁白、人物关系称谓等，如果画面里看不见，就不得写；若需要传达，转换为表情、动作、服装、伤痕、配饰、环境细节。
   5. **否定/缺失信息**：不得写“没有项圈”“没有其他人”“没有伤疤”这类纯否定句。模型画的是画面中存在的东西；不存在的东西通常直接不写。如果确实需要排除误加，用正面可见描述代替，例如“脖颈光洁”“衣着素净”而不是“没有项圈”。

## 输入

1. `book_dir`：用户指定的书籍或角色卡项目目录。用户只提供文件时，以这些文件所在的项目目录为材料范围。
2. `character_name`：用户指定的人物名或叙述者身份。
3. 用户指定的原文、人物资料、证据包和场景要求均为本次输入。

## 读取哪些文件

1. 使用文件材料设计人物时，先读取 [材料选择](references/material-selection.md)。按该文件发现材料、定位原文并选择当前画面所需段落。
2. 设计提示词时，按“立绘设计产物”第 4 项读取外观基准。使用色彩参考时，按“色彩搭配”的入口读取。

## 分析：从资料中提取什么

1. 从人物设定提取：年龄、身份、身高体型、发型、稳定穿着、固定配饰、声音气质；同时确认这些特征在时间线中的成立阶段。
2. 从调色盘/三面性/二次解释提取：性格的不同视觉状态、身体反应、控制/失控时的表情与动作、羞耻与暴露规则。
3. 从证据包提取：原文里明确写过的五官、皮肤、胸/腰/臀/腿/脚、鞋靴、发质、服饰、身体反应、性交姿势与裸露程度。
4. 从事件提取：每个事件的具体场景、动作、体位、裸露程度、情绪状态、服装残留和背景；并判断该事件处于故事哪个阶段。
5. 从开场提取：开场白对应的关键画面、人物状态、同框人物、情境氛围和镜头焦点；同样注意开场时哪些配饰/身体状态尚未成立。

6. 如果原文没有给出某一项（例如脸型、眼型），可以基于已有气质做合理设计，但必须保持稳定，并在所有提示词中复用同一套设计。

## 场景建构方法：证据优先，补充有据

1. 每个场景/事件/开场提示词都必须按以下顺序建构：

   1. **读取场景证据**：按“读取哪些文件”定位并读取原文与人物材料，找出当前场景已有的明确信息。
   2. **采用证据**：根据已读取的证据，确定画面中的地点、时间、光线、环境和人物状态。
   3. **补充画面**：资料未确定的内容，在用户授权范围内按剧情、人物性格和前后文补充。补充内容必须与已知信息一致。
   4. **记录补充内容**：提示词中保留自然描述，在对应画面文件中注明设计补充及其依据。

2. Skill 执行者不得把合理补充标为原文证据。

## 输出位置

1. 在 `book_dir` 下写入：

   ```
   source/media/
   ├── {character_name}_外观与立绘提示词.md
   ├── {character_name}_场景立绘/
   │   ├── README.md
   │   └── {character_name}_场景NN_*.md
   ├── {character_name}_事件立绘/
   │   ├── README.md
   │   └── {character_name}_事件NN_*.md
   └── {character_name}_开场立绘/
       ├── README.md
       └── {character_name}_开场NN_*.md
   ```

2. 场景文件：按“日常/工作/特殊场景/裸露性交场景”分类。
3. 事件文件：按本次要求的事件逐个生成。
4. 开场文件：按本次要求的开场逐个生成。
5. 每个提示词一个文件：**不得把所有提示词堆在一个文件里**。

## 交给 Prompt Builder

1. 本次还要求模型提示词或生成图片时，执行者根据已核对的目标底模，加载对应 Prompt Builder。
2. 将外观基准、当前剧情阶段、独立立绘提示词与设计依据的实际文件路径交给 Builder。交接时保留用户要求的景别、画幅、主体数量和创作授权。
3. Builder 将当前画面中可见的内容转换为目标模型的 Prompt。材料来源与设计补充留在设计文档中。
4. 各 Builder 按以下职责接收人物设计：

   | Prompt Builder | 接收方式 |
   | --- | --- |
   | WAI | 把画面内容映射到十五个位置。完整 Character Prompt 的采用规则由 WAI 定义。 |
   | ANIMA | 把画面内容映射到十二槽。身份、外貌、服装、动作与自然语言分别按槽位规则填写。 |
   | Krea2 | 把人物与场景组织为单条动漫正向 Prompt。 |
   | MOSS | 把画面组织为 Caption 或 Layout 草稿，再使用 MOSS 编译器。 |

5. Builder 完成其规定的语义自检、格式校验或编译后，交付对应产物。请求包含图片生成时，继续执行 `comfyui-generate`。

## 每个提示词必须包含

1. Skill 执行者按取景范围填写已确定入画的人物特征、服装和物件：

   1. **人物辨识度**：按“人物辨识度融入正文”选用外观特征。
   2. **可见外观**：按当前景别描述能看见的体型、五官、皮肤、头发和身体部位。
   3. **该阶段固定配饰/状态**：包括手链、戒指、项圈、贞操带、裸露、毛发、疤痕等。只写当前场景剧情阶段已经成立的配饰和身体状态，未来物件与状态不得提前出现。
   4. **该场景服装**：描述取景范围内实际穿着的衣物与裸露状态。
   5. **表情情绪**：具体眼神、脸红、咬牙、流泪、喘息等。
   6. **性格侧面**：按“性格与灵魂的视觉化”第 1 项第 5 子项处理。
   7. **动作姿势**：身体姿态、手脚位置、与他人互动。
   8. **背景光线**：地点、光源、氛围。
   9. **同框人物**：写清每名同框人物的年龄或年龄段（如 18 岁、25 岁、40 多岁）、性别、体型、穿着、站位、动作、表情，并明确主次关系。
   10. **确定画面状态**：提示词中不得出现“或”“也许”“可能”“或许”“或者”等可选项/推测词；必须给出唯一确定的画面状态。
   11. **多人空间关系**：按“同框人物怎么设计”处理。
   12. **画风/画质不自动添加**：除非用户明确要求，否则不得在提示词末尾添加“全身立绘、电影感光影、精细面容、8k”等画风/画质词；提示词只负责画面内容。

## 人物辨识度融入正文

1. 外观基准的采用按“立绘设计产物”第 4 项执行。
2. 从入画特征中选择能辨识人物的五官、发型、肤色或体型，融入当前动作和光线下的自然描述。
3. 配饰和身体状态按“每个提示词必须包含”第 1 项第 3 子项处理。
4. 不得使用“人物辨识度：”“核心锚点：”等标签式开头。人物特征必须写入连贯的画面描述。
5. 同一剧情阶段的描写保持一致。跨阶段特征按“外观基准文档的分章节要求”采用材料支持的状态。

## 性格与灵魂的视觉化

1. 外观基准文档必须包含一套性格/表情特征库，至少覆盖：

   1. **核心气质**：例如清冷、自卑、骄傲、依赖、倔强、麻木、羞耻、脆弱等；同一角色在不同阶段可以有气质变化，但要能看出是同一个人。
   2. **眼神特征**：按各阶段材料描述眼神。材料支持变化时，记录变化及依据。瞳孔、眼睑和视线方向必须写具体。
   3. **表情微动作**：咬唇、垂眼、皱眉、脸红到耳根、泪在眼眶打转、嘴唇颤抖、手指攥紧衣角、肩颈紧绷、膝盖内扣等。
   4. **身体语言习惯**：低头偷看、跪坐时肩背僵硬、站立时双腿并拢、被命令时先停顿再动作、紧张时手指反复摩挲裙边等。
   5. **情绪-表情映射**：把“羞耻”“恐惧”“依恋”“争宠”“麻木”等抽象情绪翻译成可见的眉眼嘴角和身体姿态。

## 外观基准文档的分章节要求

1. 外观基准文档不能只写一个笼统的“最终外貌”。外观基准文档必须按剧情章节/阶段分节，至少包含：

   1. **章节/阶段名称与范围**：如“第1-3章：校园初见”“第4-9章：项圈驯化”“第10章后：狗场/温泉圈养”，或对应事件编号范围。
   2. **该阶段已成立的外观**：记录材料支持的发型、发色、五官、肤色、身高和体型。材料明确剪发、染发、成长或身体变化时，分别记录变化前后的阶段与依据。
   3. **该阶段允许出现的服装/配饰**：如素净学生装、开裆裤、真空裙、项圈、贞操带、狗牌、兔女郎装、博士袍等。
   4. **该阶段不得出现的未来特征**：例如早期不画项圈/贞操带/剃毛，中期不画狗牌/犬籍档案等后期物件。
   5. **该阶段的身体状态**：自然阴毛、剃净、胸臀曲线、伤痕、贞操带、裸露程度等。
   6. **性格/气质与表情特征**：该阶段的眼神、眉形状态、嘴角、脸红/泪/喘息、身体语言、姿态习惯等。
   7. **参考事件/场景**：列明哪些事件或场景使用这一阶段，方便生成提示词时直接查表。

## 整体造型设计（服装/鞋靴/首饰/发型/发饰/小配件）

### 服装整体搭配

1. 当前画面有服装时，描述实际入画的衣物及其穿着状态。
2. 对入画衣物，按可见程度描述版型、长度、领口、袖型、材质、颜色和细节。
3. Skill 执行者在外观基准文档中记录常用服装的版型、材质、颜色和配件，并在各提示词中保持一致。

### 色彩搭配

1. 配色依据按 [材料选择第 4 节](references/material-selection.md#4-记录依据与设计补充)采用。
2. 补充未确定的配色时，读取 `references/color-theory.md`。在可补充范围内选择主色、辅色与点缀色。
3. 同色造型通过材质与明度区分衣物层次。
4. 补充的配色必须符合当前场景的情绪和光线。

### 材质搭配

1. 画面中有衣物或配件时，按已采用的造型描述可见材质。
2. 材质对比能帮助表现人物状态时，可在设计补充范围内采用。

### 鞋靴规格

1. 画面中有鞋靴时，描述能看见的规格：

   1. 鞋型：尖头/圆头/方头、短靴/及踝靴/及膝靴/过膝靴。
   2. 筒高：到脚踝/小腿中/膝盖。
   3. 跟型：平底/粗跟/细高跟，跟高约多少。
   4. 材质：皮革/麂皮/漆皮/帆布/缎面。
   5. 颜色与装饰：流苏、搭扣、系带、铆钉、刺绣等。

### 首饰/发型/发饰/小配件

1. 首饰：写清金属色、款式、大小、位置、光泽；不能只写“手链”“戒指”。
2. 发型：写清造型类型、长度、发质、刘海/发缝、当前状态（顺滑/湿透/汗湿/散乱）。
3. 发饰：写清大小、颜色、材质、固定位置。
4. 小配件：只要画面中出现，就要有可见形态，例如手机颜色/屏幕状态、眼镜框型、包袋材质/背法、伞是否打开/收拢、围裙花纹/系带。
5. Skill 执行者补充设计的配饰必须与已采用服装的颜色、材质、风格协调。

## 场景环境整体构建

1. 按当前取景描述已确定入画的环境。下列对象出现在画面中时，填写对应内容：

   1. **空间类型**：室内/室外、房间/街道/车内/雨地等。
   2. **时间与天气/光线**：白天/夜晚/雨天/灯光类型/明暗方向。
   3. **地面与材质**：地面材质、颜色与可见纹理。
   4. **墙面/门窗**：墙皮状态、颜色、窗户/门的位置和状态。
   5. **家具/道具/周围物体**：床、桌、椅、柜、画架、旧木箱、手机、轮椅、吊具、花瓶、纸箱等。
   6. **物体摆放关系**：主人物站在哪里，配角在哪里，家具在人物前方/后方/侧方，物体之间如何相对摆放。
   7. **环境细节**：散落的衣物、纸张、花瓣、液体、灰尘、雨水、反光等。
   8. **光线与氛围颜色**：光源位置、颜色、方向、阴影、环境主色调、人物受光/阴影位置；场景光线与氛围配色理论见 `references/color-theory.md`。

2. 场景氛围必须从该场景的具体剧情、人物关系、情绪和戏剧张力中推导，不能根据地点类型套模板词。例如旧楼不等于“压抑”，要看是掌控、偷情、失落、威胁还是对抗，再写出对应氛围。

3. 额外的污损、积水和环境物件，按“场景建构方法：证据优先，补充有据”处理。

## 配角一致性

1. 设计同框配角前，Skill 执行者读取该配角资料。
2. Skill 执行者先查找该配角自己的 `*_人物设定.md`、`*_性格调色盘.md`、`*_三面性.md`、`*_二次解释.md`，以及证据包、events、greetings 中关于该配角的描写。
3. Skill 执行者按“场景建构方法：证据优先，补充有据”采用配角资料并补充缺失内容。
4. 配角描述可比主要人物简略，仍须满足“每个提示词必须包含”第 1 项第 9 子项。

## 同框人物怎么设计

1. 画面有同框人物时，Skill 执行者先参考外观基准文档中的同框角色速查，或按“配角一致性”读取该配角资料，再按“每个提示词必须包含”填写人物信息。同框人物裸露或参与性交时，按“裸露/性交场面怎么写”第 1 项第 6 子项填写裸露状态和性器外观。
2. Skill 执行者必须明确主要人物与配角。人物称呼按“文生图可理解性：只写画面内可见信息”第 1 项第 1 子项处理。Skill 执行者可使用以下构图方式：

   1. 主要人物位于画面中心或前景，其他人物位于后方、边缘或虚化区域。
   2. 镜头焦点位于主要人物面部或身体。
   3. 配角只保留必要动作和轮廓。

3. 画面中有多人时，必须用自然语言写清空间关系，不得出现“x轴/y轴/z轴”术语，也不写无意义的厘米数。

   1. 按当前构图明确人物的相对位置、朝向与遮挡。人物关系采用已确定的材料。

   2. 同一组人物的高度/位置描述必须前后一致，不得同时写“只到膝盖”和“高出半个身子”这类互相矛盾的短语。
   3. 每个动作必须有明确主谓宾：谁的什么部位，接触/压住/抓住/插入谁的什么部位。

4. 示例：

   ```text
   一个三十岁左右的中国女性高高坐在高脚椅上，俯视着跪伏在脚边的瘦小男人；那个男人蜷缩在她脚下，仰起脸才能看见她，整个人处于她的阴影里。
   ```

5. 多人空间示例（融入正文）：

   ```text
   一个三十岁左右的中国女性被吊具固定在画面中心，骨盆位置最高，俯视着跪在她前后的两个男人；一个老年男性跪伏在她身后低处，另一个瘦小男人跪在她前方低处，两人都需要仰头看她。
   ```

## 裸露/性交场面怎么写

1. 涉及裸露或性交的事件/场景，必须写清楚生图所需的信息：

   1. **身体姿势**：站/坐/跪/躺/趴/骑乘/后入/吊具固定等。
   2. **具体动作**：插入、抽插、起落、抓握、撕扯、口交、射精等。
   3. **裸露程度**：哪些部位裸露、哪些衣服残留、交合处是否可见。
   4. **身体反应**：脸红、出汗、腿软、颤抖、乳房晃动、液体痕迹。
   5. **表情情绪**：忍耐、羞耻、兴奋、反抗、失控、冷静。
   6. **同框裸露配角**：如果画面中有其他裸露/参与性交的角色，也要写清其裸露状态和性器外观，依据证据包/原文；不能只描写主人物。

## 检查清单

1. 写完每个提示词后，Skill 执行者按“读取哪些文件”“文生图可理解性：只写画面内可见信息”“每个提示词必须包含”核对来源与正文。
2. Skill 执行者按以下章节核对适用于当前画面的要求：

   1. “人物辨识度融入正文”“性格与灵魂的视觉化”“外观基准文档的分章节要求”。
   2. “整体造型设计（服装/鞋靴/首饰/发型/发饰/小配件）”“场景环境整体构建”。
   3. 有同框人物时，核对“配角一致性”“同框人物怎么设计”。
   4. 涉及裸露或性交时，核对“裸露/性交场面怎么写”。

3. Skill 执行者按“输出位置”核对文件路径和文件粒度。

## 跳过规则

1. 以下事件/开场可以不生成提示词，但要在对应 `README.md` 中说明跳过原因：

   1. 人物没有直接出场。
   2. 只有内心活动、技术操作、无画面内容。
   3. 场景完全由他人视角构成，无法画出该人物的有效画面。
