# ComfyUI 生成

## 1. 确定任务与帮助入口

1. 执行者读取用户要求、已知产物路径和资源选择。创建图片时，执行者确定每张图片的内容与数量。无法确定某张图片的内容或数量时，执行者只询问该项。
2. 历史查询或续聊按第 2 节执行。目录查询与兼容性核对按第 3 节执行。创建图片按第 3 至 6 节执行。
3. 任务需要 CLI 时，执行者首次使用前通过官方前台 shell 读取根帮助：

   ```sh
   ELECTRON_RUN_AS_NODE=1 "$DSH_HARNESS_COMFYUI_NODE_EXECUTABLE" --expose-internals "$DSH_HARNESS_COMFYUI_CLI" --help
   ```

4. 执行者将末尾的 `--help` 替换为当前命令名与 `--help`。读取命令帮助后，执行者按帮助调用命令。同一会话复用仍在上下文中的帮助；压缩后缺少操作依据时，执行者重新读取对应 Skill 或帮助。

## 2. 查询历史与继续任务

1. 执行者从用户消息或已保存结果取得 Run ID。执行者读取 `generation run-inputs --help`，查询用户要求的参数、Seed 或 Actual Workflow，并按输入顺序报告结果。用户只要求历史查询时，执行者交付后结束。
2. 用户要求复用历史 Seed 时，执行者记录历史 Run 与待创建图片的对应关系。对应关系缺失时，执行者只询问对应项。
3. 续聊涉及已有清单或 Run 时，执行者先读取已保存清单。已有 Run 按第 6 节查询；缺少接纳结果时，执行者读取 `generation submit --help`，按帮助恢复原请求结果。
4. 用户要求重做时，执行者只为指定图片准备请求。其他图片继续使用已有 Run；请求标识的处理遵循提交帮助。

## 3. 查询并核对资源

1. 用户要求搜索 Workflow、模型或 LoRA 时，执行者通过 NoobAI MCP 查询候选。执行者按返回顺序列出标识、名称和用途。需要继续生成时，执行者等待用户选择。
2. 执行者从当前消息直接提供的 ID，以及 `comfyui-context` 的 `data.kind`、`data.id` 取得资源选择。执行者按首次出现顺序合并同类型相同 ID，并保留 LoRA 顺序。
3. 创建图片或核对兼容性时，执行者确定一个模板。用户可选择一个模型覆盖模板默认模型。模板缺失或选择不唯一时，执行者只询问对应选择。
4. 执行者通过 NoobAI MCP 取得所选模板、模型和每项 LoRA。用户未指定模型时，执行者采用模板记录的 `item.model`；默认模型为空时，执行者等待用户指定。执行者不得从 Workflow 节点或模型路线推选生成模型。
5. 返回标识与所选标识不一致时，执行者报告预期值和返回值，并等待用户重新选择。
6. 模板、采用的模型和每项 LoRA 必须关联同一底模。底模不一致时，执行者列出资源标识与底模，等待用户指定更换项。
7. 用户只要求目录查询或兼容性核对时，执行者交付查询结果与适用的比较结论，然后结束。

## 4. 确定参数与提示词

1. 执行者通过 NoobAI MCP 查询实例列表，并采用第一个实例。列表为空时，执行者报告没有可用实例，停止创建图片。
2. 执行者读取 `generation inspect-template-parameters --help`。执行者使用所选模板与实例查询参数，再按帮助核对 Prompt、Seed、单图与尺寸约束。
3. 执行者优先采用用户指定的尺寸，用提示词产物补全缺失值。尺寸意图仍缺失时，执行者询问宽高，或宽高比与像素面积。
4. 模板宽高参数直接接受目标像素宽高时，执行者采用该组参数。存在多组直接匹配时，执行者列出候选 ID 与取值，等待用户选择。需要换算、使用分辨率预设或选择近似尺寸时，执行者读取 `references/image-size-selection.md`。
5. 执行者将提示词对应到 Workflow 文本参数。结构化产物按字段提取；文本与 MOSS Layout 的 JSON 正文作为文本保留。执行者不得要求用户把已有产物改成统一的 Builder JSON。
6. 产物来自 Prompt Builder 时，执行者遵循该 Builder 的提示词合同。负向表达和画面含义由执行者判断；需要改写时，执行者先保存符合合同的产物。执行者不得用程序判断画面语义。
7. 执行者按 LoRA 顺序和资源触发词顺序核对正向 Prompt。相同触发词只保留一次；缺少完整触发词时，执行者按提示词格式补入，并保持 Builder 合同。
8. 执行者使用消息或产物中的完整 Prompt。原文件可直接使用时，执行者保留原文件；需要提取或改写时，执行者保存最终文本文件。文件引用方式按第 5 节提交帮助处理。

## 5. 确定 Seed 并提交

1. 用户为图片指定 Seed 时，执行者采用该值。用户未指定对应图片时，全部图片采用该值。用户要求固定 Seed 却未提供数值或历史 Run 时，执行者询问该输入。
2. 用户要求复用历史 Seed 时，执行者按第 2 节查询。当前 Workflow 的 Seed 参数唯一，且同名历史值为整数时，执行者采用该值；无法确定时，执行者报告对应 Run，等待用户提供数值或选择随机 Seed。
3. 其余图片使用随机 Seed。执行者读取 `generation random-seeds --help`，按帮助取得或复用 Seed，并保存 Seed 与图片顺序的对应关系。
4. Seed 不符合模板查询返回的约束时，执行者列出该值与约束。用户提供有效值或选择重新取值后，执行者继续准备请求。
5. 执行者必须先读取 `generation submit --help`，再准备清单。执行者按帮助保存请求标识、引用原文文件并合并已就绪项。每项请求保留图片顺序、所选模型与 LoRA 顺序。标题采用用户值；用户未指定时，按“图片 1”“图片 2”依次编号。
6. 执行者核对每项请求的参数、文件和资源。缺少输入或违反约束时，执行者报告图片序号与具体字段，并先处理该项。
7. 执行者提交已保存清单，并将返回的 Run ID 与图片对应保存。失败、重放与重做的技术条件按提交帮助处理。

## 6. 查询并交付

1. 用户只要求排队时，执行者交付图片标题、请求标识、完整 Run ID 和接纳结果。
2. 子会话完成提交时，将提示词文件、清单、接纳结果、完整 Run ID 与尚未完成的步骤交给主会话。Run 继续归属创建该 Run 的会话。
3. 主会话读取 `generation wait --help`，将本次请求中全部待完成 Run 登记为官方 Job。登记后，按官方 `job_output` 的等待入口取得观察结果；查找或取消观察时，分别使用 `job_list` 或 `job_kill`。具体调用按当前帮助与工具声明执行。
4. 等待尚未结束时，主会话保留观察 Job，接收完成通知后继续执行。等待期间只读取 Run ID 与状态摘要。
5. 观察完成或用户只查询已有媒体时，执行者读取 `generation resolve-media --help`，查询媒体与失败信息。
6. 需要读图、核对参数或复用 Seed 时，执行者在 Run 结束后按第 2 节读取所需参数。比较文件原文与保存参数时，只向模型上下文输出比较结果。
7. 用户要求读图、改进或多轮生成时，执行者取得媒体后继续完成对应步骤。每轮新增 Run 均按本节等待；完成请求的全部轮次和比较后，再交付最终结果。
8. 执行者按图片顺序交付媒体与完整 Run ID。失败项附状态、错误码和错误消息；需要用户处理时，执行者说明具体操作。
