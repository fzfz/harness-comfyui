# 构图决策树

## 用途和读取时机

本文件负责为当前请求生成三个完整候选构图、比较三个候选并选择唯一构图。它只处理镜头和画面空间，不负责选择语义查询接口或生成 Prompt 标签。

Skill Agent 使用 [场景分支矩阵](composition-scenario-branches.md)选定主场景并读取当前请求对应的跨位置配方后，完整读取本文件。

## 十项构图决策

Skill Agent 为每个候选依次确定以下内容：

1. 主要画面目的：当前镜头首先让观看者看清什么。
2. 主景别：特写、近景、中景、全身、远景或广景。
3. 观察角度：平视、俯视、仰视、侧面、背面或用户要求的其他角度。
4. POV 与视点位置：镜头是否采用第一人称、越肩、监视器画面或其他 POV，以及镜头位于主体的哪个方向和距离。
5. 主焦点：画面中首先吸引注意力的主体、动作、局部、道具或环境对象。
6. 主体画面位置：每名主体位于画面左侧、中央、右侧、上方、下方或画面边缘的具体安排。
7. 前景、中景和背景：各层包含的主体、道具、遮挡物和环境锚点。
8. 遮挡、裁剪和可见范围：谁遮挡谁、画面边界裁掉什么、每名主体仍可见哪些部分。
9. 景深和运动效果：清晰范围、背景虚化、运动模糊、速度线或其他与主焦点有关的表现。
10. 镜头冲突：景别、角度、POV、主体位置、遮挡、可见范围和运动效果能否同时成立。

## 三个候选的固定职责

- 候选 A：保留全部不冲突的用户明确要求，并采用最少额外推断。
- 候选 B：只改变当前请求中影响最大的一个用户未指定镜头属性，例如主景别、观察角度或 POV。
- 候选 C：只改变当前请求中影响最大的一个用户未指定空间布局或可见范围属性，例如主体布局、主焦点、遮挡或画格布局。

当前请求只剩一个可变属性时，候选 B 和候选 C 为该属性选择两个不同且能够执行的取值。分镜请求生成三套完整分镜方案，候选数量不随画格数量增加。

三个候选都保持用户明确且彼此兼容的景别、角度、POV、焦点、主体位置、遮挡和裁剪要求。候选之间的差异来自用户未指定的构图属性。

## 候选比较顺序

Skill Agent 按照以下顺序比较三个候选：

1. 用户明确指定的画面目的、主体关系、视点位置和主焦点保留程度。
2. 主景别、观察角度、POV、遮挡和可见范围的兼容性。
3. 主体位置、前中后景和环境空间对动作、动作目标及道具的容纳能力。
4. 景深和运动效果能否突出主焦点并保持动作归属清楚。
5. 前四项相同时，选择额外推断更少、末尾英文关系句更短的候选。

用户明确要求之间存在镜头冲突时，每个候选选择一组能够同时成立的要求；比较时选择保留用户明确要求最多的候选。

## 选定构图的后续用途

只有选定构图进入后续画面设计和 WAI Prompt 位置映射。后续步骤使用选定构图已经确定的十项内容。

三个候选都无法完成当前画面时，返回 [场景分支矩阵](composition-scenario-branches.md)，读取主场景对应的一份完整场景示例，然后重新生成并比较三个候选。
