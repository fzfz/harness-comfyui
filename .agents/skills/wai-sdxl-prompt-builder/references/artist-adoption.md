# WAI 画师采用规则

## 查询 WAI 画师素材

1. 本文件的画师素材指 Style 记录。查询前，通过 NoobAI MCP 确定名称精确为 `wai` 的唯一底模。
2. 底模缺失或重名时，报告实际结果并停止本次画师查询。
3. 已有画师记录 ID 时获取该记录。只有名称时按名称查询。用户只给画风方向时，按“用户未指定画师”形成查询。
4. 只采用与所需底模关联的素材。素材属于其他底模时，报告素材标识、实际底模与所需底模，停止采用该素材。

## 画师 Prompt 来源

1. 按 [Character 和 Style Prompt 来源](wai-prompt-position-order.md#character-和-style-prompt-来源)确定已采用 Style Prompt 来源及内容。
2. 用户没有替换或排除画师时，保留已采用来源与内容。
3. 用户新增画师时，保留未被排除的画师，为新增画师确定来源。
4. 用户替换画师时，移除被替换画师的来源与内容，再确定替换画师的来源。
5. 用户排除画师时，移除该画师及其内容。
6. 需要的画师 Prompt 尚未取得时，按本文件的查询分支获取。

## Style 上下文记录中的画师

1. 上下文记录的字段和处理顺序见 [当前用户消息输入合同](input-contract.md)。
2. 来源选择后仍未取得所需画师 Prompt 时，按“查询 WAI 画师素材”取得该记录的素材。
3. 按 ID 获取时，核对返回素材 ID 与所选 ID 一致。按名称查询时，按“用户指定画师”选择候选。
4. 没有可采用结果时，按“缺少画师 Prompt”处理。记录既无 ID 也无名称时，报告缺少画师名称。

## 用户指定画师

1. 用户指定画师且尚未取得所需 Prompt 时，按“查询 WAI 画师素材”查询。
2. 比较前，删除查询名称、候选名称与别名的首尾空白，再按不区分大小写的方式核对。
3. 名称或别名相等且 Prompt 非空时，候选可采用。
4. 只有 1 项符合时，采用该项。多项符合时，报告标识、名称、别名和画风说明，等待用户选择。
5. 没有可采用候选时，按“缺少画师 Prompt”处理。

## 用户未指定画师

1. 用户要求新增或选择画师，但只给画风方向时，根据画面重点确定媒介、线条、上色、明暗、纹理和配色特点。
2. 读取 [画师画风查询预置词](artist-style-query-vocabulary.md)，选取能表达这些特点的查询词。
3. 默认将查询词组合为 1 组。用户要求多个不同方向时，按方向分别组织查询词并搜索。
4. 画风说明符合该组视觉特点且 Prompt 非空的候选，列为匹配候选。
5. 用户只需 1 名画师时，按下列条件采用：

   1. 只有 1 项匹配时，采用该项。
   2. 多项匹配且用户已授权决定画面或画风时，选择最符合视觉特点的一项，保留素材标识。
   3. 其余多项匹配的请求，报告候选并等待用户选择。
   4. 没有匹配项时，按“缺少画师 Prompt”处理。

6. 用户要求同一方向采用多个画师时，报告该组匹配候选的标识、名称、别名和说明，再按下列条件处理：

   1. 用户指定数量且匹配数量相等时，采用全部匹配项。
   2. 用户指定数量且匹配数量更多时，请用户选出指定数量，再采用选中项。
   3. 用户指定数量且匹配数量不足时，报告现有数量与缺少的数量。用户调整数量或方向后，再继续。
   4. 用户没有指定数量且至少有 2 项匹配时，请用户选择 2 项或更多项。
   5. 用户没有指定数量且匹配不足 2 项时，报告数量。用户调整数量或方向后，再继续。

## 取得画师说明

1. 每名已采用画师必须有非空的完整画风说明。当前消息提供说明时采用用户说明，否则采用已取得素材中的说明。
2. 素材没有完整说明时，按“查询 WAI 画师素材”取得说明。使用来源提供的 ID；没有 ID 时使用来源提供的画师名称。查询说明不替换已采用 Prompt。
3. 按名称查询说明时，使用“用户指定画师”的名称比较方式。名称或别名相等且完整说明非空的候选可采用。
4. 只有 1 项说明候选时采用该项。多项符合时，报告标识、名称、别名与说明，等待用户选择。
5. 缺少 ID 或名称、查询无结果、所选素材没有完整说明时，报告缺少的画师信息。用户补充信息或选择其他画师后，再继续。

## 多个画师

### 分配视觉特点

1. 画师来自画风方向查询时，将该查询组的视觉特点分配给该画师。
2. 用户指定某项视觉特点的负责画师时，采用用户分配。
3. 仍有视觉特点未分配时，列出该特点和已采用画师，请用户指定负责画师。

### 核对说明与兼容性

1. 每名画师的 `style_description` 必须明确描述分配给该画师的视觉特点。
2. 不同画师对同一视觉属性的要求必须能同时成立。
3. 两项条件均满足时，共同采用这些画师。
4. 条件不满足时，列出说明未覆盖的特点与互斥要求。请用户指定保留的画师、特点及分配关系。
5. 收到完整分配后，重新核对本节条件。

### 排列画师

1. 用户指定完整顺序时，采用该顺序。
2. 用户只指定部分顺序时，列出已采用画师，请用户补齐顺序。
3. 用户没有指定顺序时，按来源顺序排列：

   1. 当前消息直接提供的 Prompt，按首次出现位置排列。
   2. Style 上下文记录，按记录首次出现位置排列。
   3. 历史来源，按用户指定复用的顺序排列。
   4. 用户指定名称后通过 MCP 取得的素材，按名称在当前消息中的首次出现位置排列。
   5. 画风方向查询取得的素材，按方向首次出现位置排列。

4. 同一方向有多个画师时，按用户选择顺序排列。直接采用全部匹配候选时，按 MCP 返回顺序排列。

### 设置画师作用

1. 主要作用指决定整体画风；辅助作用指只补充局部效果；中性作用指多名画师同等决定整体画风。
2. 用户为全部画师指定作用时，采用用户要求。
3. 用户只指定部分画师的作用时，保留已指定结果，请用户补齐其余画师的作用。
4. 用户没有指定作用，且全部画师同等承担整体画风时，全部设为中性。
5. 用户没有指定作用，且视觉特点明确区分整体和局部效果时，将负责整体的画师设为主要，将只负责局部的画师设为辅助。
6. 其余情况列出各画师负责的特点，请用户选择作用。

## 画师与其他视觉内容

1. 位置分配按 [固定顺序和唯一职责](wai-prompt-position-order.md#固定顺序和唯一职责)执行。先按“写入 artist 数组”构造画师元素，再处理冲突。
2. 记录每项 `style_description` 来自查询结果还是用户消息。说明继承对应画师 Prompt 的来源优先级。
3. 用户只提供名称且通过 MCP 取得 Prompt 和说明时，两项内容均采用查询结果的优先级。
4. 将每项非画师风格、细节效果和光线内容，与每名画师说明比较。互斥时，按 [Prompt 冲突规则](prompt-conflict-rules.md)确定保留内容。
5. 被删除的要求属于画师说明时，移除该画师的来源、内容和对应画师元素。被删除的要求属于普通视觉内容时，删除对应位置中的内容。
6. 移除画师后，删除该画师的特点分配。仍有特点需要分配时，按“分配视觉特点”处理。
7. 移除后仍有多名画师时，重新核对说明、兼容性、排列和作用。

## 写入 artist 数组

1. 按 [WAI 画师语法](wai-artist-syntax.md)，将每名画师的 Prompt 转为画师数组元素。

## 缺少画师 Prompt

1. 完成来源选择后仍没有非空 Prompt 的画师，不得写入画师数组。
2. 查询没有可用结果，但当前消息已提供非空画师 Prompt 时，继续采用当前 Prompt。
3. 仍无 Prompt，但用户已指定媒介、线条、上色、明暗、纹理或配色时，使用这些描述继续构造。
4. 上述内容均未提供时，报告缺少的 Prompt 与视觉特点。用户补充后，再继续构造。
