# 画师采用规则

## 用途和读取时机

本文件规定 Skill Agent 何时采用 UI 已选画师、何时查询一个或多个画师、如何比较候选，以及如何把被采用画师交给 `artist` 位置。

UI 已选 Style 的字段和处理顺序由 [当前轮输入合同](input-contract.md)定义。

出现以下任一情况时，Skill Agent 必须读取本文件：

- UI 已经选择一个或多个 Style；
- 用户指定、增加、替换或排除具体画师；
- 用户没有指定具体画师，但完整画面设计需要确定一个或多个匹配的画师方向；
- 用户要求混合多个画师；
- 被采用画师还需要与普通画风、媒介效果或光线共同使用。

第一次调用 Style 接口前，Skill Agent 还必须完整读取[语义查询接口与调用流程](semantic-tool-orchestration.md)。

## UI 已选画师

用户本轮没有替换或排除 UI 已选画师时，Skill Agent 使用语义查询接口文档规定的 UI 已选画师内容。用户本轮明确增加画师时，Skill Agent 保留未被排除的 UI 已选画师，并为新增画师完成查询和采用。用户本轮明确替换或排除画师时，按照用户本轮要求处理。

## 用户指定具体画师

Skill Agent 必须使用用户给出的画师名称设计 Style 查询。查询返回候选后，Skill Agent 按照语义查询接口文档规定的字段用途完成身份核对、画风比较和画师提示词采用。

## 用户没有指定具体画师

用户没有指定具体画师，而完整画面设计需要画师方向时，Skill Agent 必须按照以下顺序处理：

1. 根据用户要求、选定构图、主体、动作、环境和画面重点设计目标画面风格，并列出需要画师承担的视觉特征。
2. 读取[画师画风查询预置词](artist-style-query-vocabulary.md)，选择能够准确描述目标视觉特征的查询词。
3. 为每个独立画师方向建立一个 Style 查询目标，并使用选定的查询词编写对应的查询文本。
4. 按照语义查询接口文档规定的字段用途核对候选身份，并比较各候选与目标画面风格的匹配程度。
5. 采用能够共同完成目标画面风格的一个或多个候选，并取得语义查询接口文档规定的画师提示词。

## 多个画师

采用多个画师时，Skill Agent 必须分别判断每名画师在目标画面中的作用，并按照语义查询接口文档检查多个候选画风能否共同使用。

- 用户明确指定画师顺序或主次时，按照用户要求排列。
- 用户没有指定主次且多个画师承担同等作用时，全部作为平衡画师。
- 完整画面设计明确需要一个主要画师方向和一个或多个辅助方向时，分别确定主要画师和辅助画师。

每名画师的画师提示词必须分别交给[WAI 画师语法](wai-artist-syntax.md)处理。

## 与普通画面风格的关系

具体画师使用 Style 查询并进入 `artist`。普通画风、媒介、渲染、摄影效果、数字效果、整体画面情绪和光线使用 Prompt-term 查询或对应位置允许的自主设计内容，分别进入 `non_artist_style`、`detail_mood` 或 `lighting`。

Skill Agent 按照语义查询接口文档规定的字段用途判断画师与这些普通视觉内容能否共同使用。

## 缺少画师 Prompt

Style 查询过程按照[语义查询接口与调用流程](semantic-tool-orchestration.md)处理。

只有语义查询接口文档允许的来源提供合法画师提示词时，Skill Agent 才创建对应画师内容。没有可用画师提示词时，不创建该画师的 `artist` 内容。

## 完成检查

Skill Agent 必须确认：

- 用户本轮对画师的增加、替换和排除要求已经落实；
- 每个采用候选已经按照语义查询接口文档完成身份核对、画风比较和画师提示词采用；
- 多个画师具有明确顺序和作用；
- 普通画风、媒介、摄影效果和光线没有作为 Style 画师内容处理。
