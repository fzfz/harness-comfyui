# WAI Prompt 自检

## 用途、执行顺序和通过条件

Skill 执行者按照本文件的章节顺序检查最终 Prompt。某条检查不满足本条规定的通过条件时，本项检查不通过。失败项已经规定报告、修正、重新检查或停止动作时，Skill 执行者直接执行该项规定的动作。失败项没有规定处理动作并且只涉及主场景选择或 `positions` 数据结构时，Skill 执行者按照本条规定的通过条件修正选择或数据结构。其他失败项需要修改或补充最终 Prompt 内容时，Skill 执行者先按照“用户要求与输入采用”一节确定问题内容的来源优先级。修正只涉及较低优先级来源或 Skill 执行者补充的内容时，Skill 执行者修改或补充该内容。修正会改变当前用户消息中的明确要求，或者最高优先级来源仍包含多项互斥内容时，Skill 执行者列出冲突内容、每项内容的来源和可保留的选项，并等待用户选择；用户尚未选择时停止本轮自检。每次修改、补充或用户选择完成后，Skill 执行者重新执行 [Prompt 冲突规则](prompt-conflict-rules.md) 和 [WAI Prompt 权重规则](prompt-weighting.md)，再从本文件的“用户要求与输入采用”一节开始重新检查。只有全部检查均通过，并且不存在等待用户选择的内容时，本轮自检才通过。

## 用户要求与输入采用

- 最终 Prompt 包含冲突处理后保留的全部正向内容。检查范围包括当前用户消息中的明确要求、Character 上下文记录和 Style 上下文记录中已经采用的 `data.prompt_text`、用户指定采用的历史 Generation Run 输入、已采用的 Character 查询结果、已采用的 Style 查询结果、已采用的 Prompt-term 查询结果和 Skill 执行者补充的内容；Character 查询结果和 Style 查询结果检查 `prompt_text`，Prompt-term 查询结果检查 `canonical_tag`。每项保留内容必须按照“Prompt 位置集合”一节归入对应位置。遗漏任一保留内容时，本项检查不通过；Skill 执行者补入该内容并重新执行全部检查。补入内容会产生最高优先级冲突时，Skill 执行者列出遗漏内容、冲突内容及各自来源，并等待用户选择；用户尚未选择时停止本轮自检。
- Skill 执行者逐项检查当前用户消息中的明确排除要求。某项明确排除要求与当前用户消息中的另一项明确正向要求无法同时满足时，Skill 执行者列出该排除要求、该正向要求和可保留的选项，并等待用户选择；用户尚未选择时，本项检查不通过，Skill 执行者停止本轮自检。不存在上述同级冲突时，该排除要求保持有效，并优先于 Character 上下文记录、Style 上下文记录、用户指定采用的历史 Generation Run 输入、已采用的查询结果和 Skill 执行者补充的内容。最终 Prompt 出现有效排除要求所排除的对象、属性值、动作、环境、效果、画师、风格、媒介、输出形态、生产用途或主体关系时，本项检查不通过；Skill 执行者移除与该排除要求冲突的较低优先级内容，并重新执行全部检查。
- 最终 Prompt 中两项内容在同一画格、同一时点以及同一主体或同一环境对象的同一属性上无法同时成立时，Skill 执行者按照以下来源优先级确定保留内容：第一，当前用户消息中的明确要求；第二，当前用户消息中对应的 Character 上下文记录或 Style 上下文记录；第三，用户指定采用的历史 Generation Run 输入；第四，已采用的查询结果，其中 Character 查询结果和 Style 查询结果使用 `prompt_text`，Prompt-term 查询结果使用 `canonical_tag`；第五，Skill 执行者补充的内容。已经通过不同画格编号或不同画格名称明确分隔为变化前后状态的内容不属于互斥内容。最高优先级来源只有一项互斥内容时，Skill 执行者保留该项内容；最高优先级来源包含多项互斥内容时，Skill 执行者向用户列出这些内容并等待用户选定一项。用户尚未选择时，本项检查不通过。
- 同一主体或同一环境对象在同一画格、同一时点的两项内容虽然描述不同属性，但两项内容仍然无法同时成立时，这两项内容也属于互斥内容。Skill 执行者按照上一条规定的来源优先级和同优先级选择规则确定保留内容。
- 当前用户消息、当前用户消息中的 Character 上下文记录或 Style 上下文记录、用户指定采用的历史 Generation Run 输入、已采用的 Character 查询结果、已采用的 Style 查询结果和已采用的 Prompt-term 查询结果均未提供某个必填 Prompt 位置所需内容时，Skill 执行者为该位置补充内容。补充内容必须与冲突处理后保留的全部正向内容同时成立，不得违反本节排除要求冲突处理规则保留的排除要求，并且不得改变这些正向内容。不存在符合上述条件的补充内容时，本项检查不通过；Skill 执行者列出缺失位置、与该位置冲突的每项保留内容及其来源，以及阻止补充的每项保留排除要求，并请求用户指定需要修改或移除的保留内容或排除要求。用户尚未指定时，Skill 执行者停止本轮自检；用户完成指定后，Skill 执行者按照来源优先级更新内容并重新执行全部检查。

## Prompt 位置集合

- Skill 执行者根据冲突处理后保留的全部内容，从 [场景分支矩阵](composition-scenario-branches.md)“主场景”列中选择一个且仅一个主场景。任一保留内容要求多个画格、前后变化、过程或状态对比时，选定主场景必须是“分镜与状态变化”。
- Skill 执行者建立最终 Prompt 必须使用的位置集合：将选定主场景在 [场景分支矩阵](composition-scenario-branches.md)“必须完成的 WAI Prompt 位置”列中列出的全部位置纳入集合；将本轮用于选择、改写或校验 Prompt 内容且包含“位置映射”表的每个 Markdown 参考文件在该表中列出的全部位置纳入集合；将“用户要求与输入采用”一节确定的每项保留内容按照本节的内容分类与 Prompt 位置映射归入对应的一个或多个位置，并将这些位置纳入集合。当前用户消息只排除某类内容且没有要求该类最终内容时，该排除要求不增加对应位置。所有位置名称必须属于下一条列出的十五个位置；参考文件出现其他位置名称时，Skill 执行者报告该参考文件的相对路径和非法位置名称，然后停止本次执行。`positions` 实际包含的位置必须与该集合完全一致。
- 用于构造最终 Prompt 的 `positions` 必须是一个至少包含一个属性的对象。该对象只允许使用 `quality`、`artist`、`subject`、`character`、`appearance`、`outfit`、`action`、`expression_reaction`、`camera_composition`、`environment`、`detail_mood`、`lighting`、`non_artist_style`、`technical` 和 `relation_narrative`，并按照这个顺序排列实际使用的位置。每个位置的值必须是至少包含一个单行非空字符串的数组；没有最终内容的位置不得出现在 `positions` 中。
- Skill 执行者按照以下映射检查最终 Prompt 中每项内容的所属位置；本轮 Character Prompt 已经包含的外貌或服装内容按照下一条处理：质量写入 `quality`；画师 Prompt 写入 `artist`；主体总数、性别组合和主体类别写入 `subject`；本轮 Character Prompt 写入 `character`；外貌写入 `appearance`；服装写入 `outfit`；动作写入 `action`；表情和身体反应写入 `expression_reaction`；镜头和构图写入 `camera_composition`；地点、空间结构、环境对象、时间、季节、天气和环境状态写入 `environment`；图像表面质感、摄影效果、数字后期效果、运动表现和画面情绪写入 `detail_mood`；光线写入 `lighting`；非画师风格和创作媒介写入 `non_artist_style`；输出形态和生产用途写入 `technical`；前十四个位置不能唯一表达的主体关系、主体分组、动作归属、动作对象、物件或接触关系归属和空间关系，以及跨画格关系和因果关系写入 `relation_narrative`。
- Skill 执行者按照 [WAI Prompt 位置顺序与职责](wai-prompt-position-order.md)确定每条已采用 Character Prompt 来源和对应的本轮 Character Prompt。用户没有新增、替换或排除角色外貌或服装时，本轮 Character Prompt 完整保留来源文本。用户新增角色外貌或服装时，本轮 Character Prompt 保持不变，新增内容进入 `appearance` 或 `outfit`。用户替换角色外貌或服装时，本轮 Character Prompt 删除直接冲突的原标签，替换内容进入 `appearance` 或 `outfit`。用户排除某项角色外貌或服装时，本轮 Character Prompt 删除被排除的标签，且最终 Prompt 不加入排除内容。本轮 Character Prompt 已经包含的外貌或服装不在 `appearance` 或 `outfit` 中重复写入；`subject` 仍然表达整幅画面的主体总数、性别组合和主体类别。

## 主体、角色和外貌

- `subject` 中的主体总数与 `camera_composition` 安排的主体数量一致；`camera_composition` 对每个主体的指代均能对应到 `subject` 已经确定的主体性别和主体类别，并且没有增加、遗漏或改变任何主体。
- 每条本轮 Character Prompt 包含单角色数量标签时，`subject` 仍然表达整幅画面的主体总数、性别组合和主体类别；单角色数量标签不得替代整幅画面的主体信息。
- 最终 Prompt 的文字必须把每条本轮 Character Prompt 唯一对应到画面中的一个具体主体。画面包含多个主体时，该对应关系必须通过角色名称、主体称谓、画格编号、画格名称或画面位置中的至少一种方式明确表达。
- 画面包含多个主体时，每项外貌、服装、动作、表情和身体反应均能确定其所属主体。
- 最终 Prompt 中同一主体的身份、外貌、服装和身体状态能够同时成立。

## 动作、反应和主体关系

- 需要动作对象的每个动作均能确定该动作对象。
- 每个主体的姿态、动作方向、身体朝向、接触点、支撑点和动作结果能够同时成立。
- `expression_reaction` 中每个主体的表情、视线和身体反应符合该主体当前所处的动作阶段。
- 除 `relation_narrative` 外的十四个 Prompt 位置所承载的内容不能唯一表达动作归属、动作对象或主体关系时，Skill 执行者将该关系写入 `relation_narrative`。对应英文短句必须明确写出涉及的主体；关系涉及动作时，还必须明确写出动作。

## 镜头、空间和环境

- `camera_composition` 确定的景别和遮挡必须使以下最终内容可见：冲突处理后保留的全部主体、动作、表情、视线、身体反应和环境对象，`appearance` 与 `outfit` 中的全部内容，以及本轮 Character Prompt 中明确要求出现在取景范围内的外貌或服装内容。任一上述内容超出取景范围或被完全遮挡时，本项检查不通过；Skill 执行者按照“用户要求与输入采用”一节的来源优先级修正景别、遮挡或该项内容。修正会改变当前用户消息中的明确要求时，Skill 执行者列出冲突选项并等待用户选择；用户尚未选择时停止本轮自检。
- `camera_composition` 中的相机角度、POV、焦点、主体位置、前景、中景、背景、遮挡、裁剪和景深能够同时成立。
- 最终 Prompt 中的画面左侧和右侧、画面前方和后方、画面上方和下方以及相对远近以 `camera_composition` 确定的相机位置、相机朝向和取景范围为判断依据；主体或环境对象的内外关系和包含关系以 `environment` 确定的空间结构为判断依据。
- `environment` 必须明确能够容纳全部主体位置、动作范围和相机位置的地点或空间结构。最终 Prompt 采用环境对象时，`environment` 还必须明确这些环境对象的位置，并保证这些位置与主体位置、动作范围和相机位置同时成立。
- `environment` 中的时间、季节、天气和环境状态能够同时成立。

## 光线、画师和画师权重

- `lighting` 中每个可见阴影在承影面上的延伸方向必须背离产生该阴影的光源；存在多个光源时，每个阴影必须能够对应到产生该阴影的具体光源。冲突处理后保留的任一内容明确要求通过光线、色彩或对比度突出某个主体、环境对象或空间层次时，`lighting` 必须写明被突出对象，并写明用于突出该对象的光源方向、受光强弱、明暗对比或色彩对比中的至少一项。`lighting` 指定的光源位置、受光主体和受光环境对象必须与 `camera_composition` 和 `environment` 已经确定的主体位置、环境对象位置及空间关系同时成立。任一条件不满足时，本项检查不通过；Skill 执行者按照“用户要求与输入采用”一节的来源优先级修正光源、阴影、受光对象或空间关系。修正会改变当前用户消息中的明确要求时，Skill 执行者列出冲突内容和可保留的选项，并等待用户选择；用户尚未选择时停止本轮自检。
- `artist` 中的每个数组元素只表达一位已采用画师，并且该数组元素通过 [WAI 画师语法](wai-artist-syntax.md) 的全部检查。
- 每位已采用画师具有 [画师采用规则](artist-adoption.md) 确定的主要、辅助或中性作用，并且只具有其中一种作用。尚未确定某位画师的唯一作用时，本项检查不通过；Skill 执行者按照画师采用规则列出该画师以及可供用户选择的作用选项，并在用户选定一种作用前停止本轮自检。Skill 执行者按照本文件“权重”一节为每个画师数组元素确定实际采用的权重形式，并使用 [WAI Prompt 权重规则](prompt-weighting.md) 检查该形式；检查不通过时，Skill 执行者按照“权重”一节规定的失败动作处理。

## 权重

- 本文件中的 `payload` 指一个 Prompt 数组元素承载的内容文本；在 `(payload)` 和 `(payload:weight)` 中，最外层括号、分隔冒号和 `weight` 不属于 `payload`。除 `relation_narrative` 外的十四个 Prompt 位置中，每个数组元素均采用裸 `payload`、`(payload)` 或 `(payload:weight)` 三种形式之一；`(payload:weight)` 中的 `weight` 必须符合 `prompt-weight-policy.json` 的 `syntax.explicit_weight`，每个数组元素最多包含一层权重外层。
- 对于前十四个 Prompt 位置中同一位置内解析后的同一 `payload`，Skill 执行者按照以下顺序确定实际采用的最高优先级权重形式：当前用户消息中的用户直接形式或用户确认形式、当前用户消息中的 Character 上下文记录或 Style 上下文记录、用户指定采用的历史 Generation Run 输入、已采用的 Character 查询结果或 Style 查询结果、Skill 执行者选择的自主权重形式。Prompt-term 查询结果的 `canonical_tag` 只提供 `payload`，不提供来源权重形式。同一 `payload` 出现在不同 Prompt 位置时，各位置分别确定权重形式。最终形式必须等于该位置实际采用的最高优先级形式，并且必须通过 [WAI Prompt 权重规则](prompt-weighting.md) 的解析检查；未被采用的较低优先级形式不影响本项结果。自主权重形式不合法时，Skill 执行者按照 WAI Prompt 权重规则修正并重新检查。实际采用的来源形式不合法，或者该位置实际采用的最高优先级仍包含多个互斥形式时，本项检查不通过；Skill 执行者列出 Prompt 位置、`payload`、冲突形式、每个形式的来源和合法选择并等待用户。用户尚未选择时，Skill 执行者停止本轮自检。
- `prompt-weight-policy.json` 的 `recommendations.unweighted_quality.content` 定义固定质量内容。除非当前用户消息明确排除或替换某项固定质量内容，并且该要求经过“用户要求与输入采用”一节的排除要求冲突处理后仍然保留，否则该项固定质量内容属于应保留的固定质量内容。`quality` 必须按照定义数组的原顺序包含全部应保留的固定质量内容；每项应保留的固定质量内容必须恰好出现一次，并且使用未加权形式。固定质量内容缺失、顺序错误或重复时，本项检查不通过；Skill 执行者补入缺失内容、恢复定义顺序或删除重复内容，并重新检查固定质量内容的顺序、数量和形式。上述修正会改变当前用户消息中的明确要求时，Skill 执行者列出冲突内容和可保留的选项，并等待用户选择；用户尚未选择时停止本轮自检。某项应保留的固定质量内容按照上一条确定的实际采用形式为默认权重或显式数值权重时，本项检查不通过；Skill 执行者报告该内容、实际采用形式及其来源，并等待用户选择未加权形式或其他质量内容。用户尚未选择时，Skill 执行者停止本轮自检；用户完成选择后，Skill 执行者重新检查固定质量内容的顺序、数量和形式。`quality` 中不属于固定质量内容的数组元素按照上一条规定的来源优先级和 [WAI Prompt 权重规则](prompt-weighting.md) 检查。
- Skill 执行者分别在前十四个 Prompt 位置内按照解析后的 `payload` 合并重复数组元素，并且只保留该 `payload` 的一个选定最终形式。两个数组元素的画格标识不同时，二者属于不同 `payload`，不得因为画格标识以外的文本相同而合并。同一 `payload` 出现在不同 Prompt 位置时，各位置分别保留一个选定最终形式。
- 高于中性强度的数组元素数量、计数方式、数量上限和超限后的用户选择结果必须通过 [WAI Prompt 权重规则](prompt-weighting.md)“高于中性强度的数量”一节的全部检查。任一检查不通过时，Skill 执行者按照该节列出计入元素并等待用户完成合法选择；用户回复前停止本轮自检。用户完成选择后，Skill 执行者重新统计数量。
- `relation_narrative` 中的关系文字没有使用 `(payload)` 或 `(payload:weight)` 外层。

## 分镜

画面包含多个画格时，最终 Prompt 必须满足以下条件：

- 每个画格均明确该画格内的全部主体。对于每个主体，最终 Prompt 必须明确其身份，以及已经采用且适用于该主体的外貌、服装状态、姿态、表情、视线和身体反应；不适用于该主体类别的属性不要求补充。最终 Prompt 还必须明确该画格中已经采用的动作、镜头、环境和光线。任一适用内容缺失或主体归属不明时，本项检查不通过。补充画格标识、主体标识或缺失内容只涉及较低优先级来源或 Skill 执行者补充的内容时，Skill 执行者完成补充并重新执行全部检查。补充会改变当前用户消息中的明确要求，或者最高优先级来源仍包含多项互斥内容时，Skill 执行者列出缺失内容、冲突内容、每项内容的来源和可保留的选项，并等待用户选择；用户尚未选择时停止本轮自检。用户完成选择后，Skill 执行者应用用户选择并重新执行全部检查。
- 跨画格保持不变的主体身份、外貌、服装、环境和光线可以采用全局表达或逐画格表达。采用全局表达时，最终 Prompt 必须明确该内容作用于全部相关画格，并且只保留一次；采用逐画格表达时，每个相关画格必须使用相同的描述文本和权重形式，并使用不同的画格编号或画格名称标明所属画格。同一内容混用两种表达方式、遗漏相关画格或在相关画格之间出现不同文本或权重形式时，本项检查不通过。某一来源明确要求使用全局表达或逐画格表达时，Skill 执行者按照“用户要求与输入采用”一节的来源优先级选择表达方式、描述文本和权重形式；没有来源指定表达方式时，Skill 执行者采用全局表达。最高优先级来源包含多项互斥的表达方式、描述文本或权重形式时，Skill 执行者列出冲突内容、每项内容的来源和可保留的选项，并等待用户选择；用户尚未选择时停止本轮自检。完成统一或应用用户选择后，Skill 执行者重新执行重复内容检查和本文件的全部检查。
- 每项跨画格变化均写明变化对象和该对象在变化前后的具体内容。经过“权重”一节保留的每项固定质量内容作用于整条最终 Prompt，只在全局 `quality` 中出现一次，不属于任何单个画格，也不得作为跨画格变化对象。允许变化的对象可以是：固定质量内容以外的质量内容；主体数量、主体类别、主体身份、主体外貌、主体服装、主体动作、主体表情、主体视线或主体身体反应；地点、空间结构、环境对象、时间、季节、天气或环境状态；景别、相机角度、POV、焦点、主体位置、前景、中景、背景、遮挡、裁剪或景深；图像表面质感、摄影效果、数字后期效果、运动表现或画面情绪；光源位置、光源方向、光源色温、受光主体、受光环境对象、受光强弱、阴影、明暗对比或色彩对比；画师、非画师风格或创作媒介；输出形态或生产用途；主体关系。
- 最终 Prompt 表达画格先后顺序、时间变化、状态变化或因果关系时，Skill 执行者将每项关系写入 `relation_narrative`。用于表达关系的每个英文短句必须使用画格编号或画格名称标明涉及的画格。表达先后顺序时，短句写明哪个画格在前、哪个画格在后；表达时间变化或状态变化时，短句写明上一条所列的变化对象及其变化前后的具体内容；表达因果关系时，短句写明原因事件和结果事件。
