# WAI Prompt 自检

## 执行顺序与修正

1. 按本文件的章节顺序检查最终 Prompt。
2. 主场景或位置结构不符合要求时，按“Prompt 位置集合”修正。
3. 内容互斥时，按 [Prompt 冲突规则](prompt-conflict-rules.md)决定保留内容。
4. 缺少内容时，先核对本轮全部已采用来源。只补充这些来源均未提供的内容。
5. 修正需要改变用户明确要求时，列出问题内容、来源与可保留选项。用户选择后，再执行依赖该选择的步骤。
6. 每次修正或采用用户选择后，重新执行冲突处理、[权重设计](prompt-weighting.md)和本文件的全部检查。
7. 全部检查通过，且没有待用户决定的事项时，自检完成。

## 用户要求与输入采用

1. 检查范围包含 [SKILL.md 第 1 节](../SKILL.md#1-读取本轮输入)中采用的全部来源。冲突处理后保留的每项正向内容均已进入 Prompt。
2. 用户的有效排除要求均已采用。排除要求与正向要求冲突时，按“执行顺序与修正”处理。
3. 同一画格中不能同时成立的内容，均已完成 [冲突判断和来源优先级](prompt-conflict-rules.md#冲突判断和来源优先级)处理。
4. 必选位置仍缺少内容时，核对 SKILL.md 第 1 节的全部已采用来源。补充内容必须能与保留的正向内容和排除要求同时成立。
5. 无法补充必选位置时，列出缺失位置、冲突内容及来源，请用户决定修改项。

## Prompt 位置集合

1. 主场景符合 [场景分支矩阵](composition-scenario-branches.md)。需要多个画格、前后变化、过程或状态对比时，采用“分镜与状态变化”。
2. 位置集合符合 [确定本轮位置集合](wai-prompt-position-order.md#确定本轮位置集合)。全部必选位置均有实际内容。
3. 各位置的内容与顺序符合 [固定顺序和唯一职责](wai-prompt-position-order.md#固定顺序和唯一职责)。格式按 SKILL.md 第 6 节的校验器帮助处理。
4. 角色来源的采用和修改符合 [Character 来源内容](wai-prompt-position-order.md#character-来源内容)。

## 主体、角色和外貌

1. `subject` 中的主体总数与构图安排一致。构图中的每个主体均能对应到已确定的性别和类别。
2. 每条 Character Prompt 均唯一对应到画面中的主体。多主体画面使用名称、称谓、画格标识或画面位置明确对应关系。
3. 每项外貌、服装、动作、表情和身体反应均能确定所属主体。
4. 同一主体的身份、外貌、服装和身体状态能同时成立。

## 动作、反应和主体关系

1. 需要动作对象的动作，均已明确动作对象。
2. 每个主体的姿态、动作方向、身体朝向、接触点、支撑点和动作结果能同时成立。
3. 表情、视线和身体反应符合当前动作阶段。
4. 关系短句的使用符合 [易混淆内容的位置边界](wai-prompt-position-order.md#易混淆内容的位置边界)。

## 镜头、空间和环境

1. 当前取景和遮挡能显示已保留的主体、动作、反应和环境对象。
2. `appearance`、`outfit` 中的内容，以及 Character Prompt 中明确要求入画的特征均可见。
3. 相机角度、POV、焦点、主体位置、前中后景、遮挡、裁剪和景深能同时成立。
4. 左右、前后、上下和远近关系，以相机位置、朝向和取景范围为依据。
5. 内外关系与包含关系符合环境的空间结构。
6. 环境能容纳主体位置、动作范围和相机位置。环境对象的位置与这些范围能同时成立。
7. 时间、季节、天气和环境状态能同时成立。

## 光线、画师和作用

1. 每个阴影在承影面上的延伸方向，均背离对应光源。多个光源产生的阴影分别有明确来源。
2. 画面需要突出某个对象或空间层次时，光线描述已明确突出对象与使用的明暗或色彩对比。
3. 光源、受光对象与构图中的空间关系能同时成立。
4. 画师元素通过 [WAI 画师语法](wai-artist-syntax.md)的检查。
5. 每位已采用画师的作用符合 [多个画师](artist-adoption.md#多个画师)的分配结果。

## 权重

1. 权重解析、来源选择、固定质量内容的未加权形式与强度上限，均通过 [WAI Prompt 权重规则](prompt-weighting.md)的检查。
2. 固定质量内容按 `prompt-weight-policy.json` 的 `recommendations.unweighted_quality.content` 核对。用户明确替换或排除且通过冲突处理的内容，按保留结果处理。
3. 保留的固定质量内容按定义顺序各出现 1 次。缺失、重复或顺序错误时，修正后重新检查。
4. 同一位置中相同 `payload` 只保留选定的最终形式。不同位置分别处理。
5. 画格标识不同的内容分别处理，不得只因标识以外的文本相同而合并。
6. `relation_narrative` 中的关系文字保持未加权。

## 分镜

### 画格内容

1. 每个画格已明确全部主体。
2. 每个主体均有已采用且适用的身份、外貌、服装、姿态、表情、视线和身体反应。主体类别不适用的属性不必补充。
3. 每个画格已明确采用的动作、镜头、环境和光线。
4. 内容缺失或归属不明时，按“执行顺序与修正”处理。

### 跨画格保持不变的内容

1. 身份、外貌、服装、环境和光线保持不变时，选择全局表达或逐画格表达。
2. 采用全局表达时，明确适用的全部画格，同一内容只保留 1 次。
3. 采用逐画格表达时，每个适用画格使用相同文本和权重形式，并以画格标识区分。
4. 来源指定表达方式时，按 SKILL.md 第 1 节的来源优先级采用。来源没有指定时，采用全局表达。
5. 同一内容混用表达方式、遗漏画格、文本或权重不一致时，统一后重新自检。最高优先级仍有互斥要求时，请用户选择。

### 跨画格变化与关系

1. 每项变化已写明对象及其变化前后的具体状态。
2. 保留的固定质量内容作用于整条 Prompt，只在全局 `quality` 中出现 1 次，不作为画格变化对象。
3. 其余内容的变化按 [固定顺序和唯一职责](wai-prompt-position-order.md#固定顺序和唯一职责)分配到对应位置。
4. 画格的先后、时间、状态与因果关系写入 `relation_narrative`。每个英文短句使用画格标识。
5. 顺序短句明确前后画格；变化短句明确变化对象和前后状态；因果短句明确原因事件和结果事件。
