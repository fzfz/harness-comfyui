# ComfyUI 图片审阅

## 1. 取得 Run 参数与图片

1. 执行者从用户消息取得 Run ID。用户指代此前生成结果时，执行者从该结果取得对应 ID。缺少 ID 时，执行者询问并等待补充。
2. 首次使用受管 CLI 前，执行者通过官方前台 shell 读取根帮助：

   ```sh
   ELECTRON_RUN_AS_NODE=1 "$DSH_HARNESS_COMFYUI_NODE_EXECUTABLE" --expose-internals "$DSH_HARNESS_COMFYUI_CLI" --help
   ```

3. 执行者将末尾的 `--help` 替换为 `generation resolve-media --help`，读取该命令的帮助。
4. 执行者查询所选 Run 的媒体，设置 `include_parameters: true`，并保留输入顺序和重复项。
5. 执行者记录各 Run 的状态和错误。
6. 执行者按命令帮助处理未完成的 Run 和逐项查询错误。
7. Run 的状态为 `failed`、`cancelled` 或 `submission_unknown` 时，执行者报告状态与错误，并审阅已保存图片。
8. 同一会话复用仍在上下文中的帮助。压缩后缺少操作依据时，执行者在对应调用前重新读取帮助。

## 2. 逐图读取

1. 执行者首次读取图片前，将第 1 节入口末尾的 `--help` 替换为 `image inspect --help`，读取该命令的帮助。
2. 用户指定关注点、返回格式或读图提示词时，执行者将要求写成完整的 `prompt`，并传给对应图片。相同要求使用同一份提示词；用户没有指定要求时，执行者省略 `prompt`。
3. 执行者按 Run 顺序和各 Run 的图片顺序，依照 `image inspect` 帮助取得观察结果，使用媒体结果提供的 `file_path`。没有已保存图片时，执行者说明该 Run 尚无可审阅图片。
4. 执行者按命令帮助处理读取失败。仍未取得观察结果时，执行者记录媒体标识、路径、错误码和错误消息。用户或宿主取消调用时，执行者报告取消并结束执行。

## 3. 对比生成意图与可见结果

1. 执行者必须为每个 Run 独立比较原始 `parameters` 与成功取得的图片 `observation`。生成意图以 Prompt 参数为准。
2. 执行者比较以下内容：

   1. 主体；
   2. 数量；
   3. 外观；
   4. 姿态；
   5. 构图；
   6. 镜头；
   7. 场景；
   8. 光线；
   9. 风格；
   10. 文字。

3. 用户明确指定关注点时，执行者必须在对比中使用该关注点。
4. 执行者将宽高、seed、steps、CFG、sampler 和 scheduler 等运行参数作为诊断上下文。

5. 执行者必须逐项区分：

   1. 符合意图：图片观察明确支持的生成意图；
   2. 缺失或偏弱：图片观察明确描述为缺失或表现偏弱的生成意图；
   3. 意外内容：图片观察明确出现，但生成意图没有要求的内容；
   4. 不确定：图片观察未提及、描述为遮挡或无法确认的内容。

6. 多张图片属于同一 Run 时，执行者必须分别列出图片差异，再归纳该 Run 的重复问题和偶发问题。

## 4. 编写改进 Prompt

1. 对已取得图片 `observation` 的每个 Run，执行者必须编写一份改进 Prompt。
2. 执行者保留符合用户意图的内容。
3. 执行者强化缺失或偏弱的内容。
4. 执行者将含糊表达改为明确的主体、关系、位置、镜头和视觉属性。
5. 只有意外内容影响用户目标时，执行者才可添加针对性约束。
6. 执行者必须保持原 Prompt 的语言和标签体系。
7. 执行者必须按原始 `parameters` 中的参数名分别给出每个已有 Prompt 参数的改进值，并保留各参数的用途。

## 5. 返回结果

1. 执行者必须按第 1 节取得的 `run_id` 顺序返回：

   1. Run 标题与原始 Prompt 参数；
   2. 每张图片的 `media_id`、观察结果或读取错误；
   3. 符合意图、缺失或偏弱、意外内容与不确定内容；
   4. 执行者已取得该 Run 的图片 `observation` 时，返回该 Run 的改进 Prompt；全部图片读取失败时，说明未生成改进 Prompt 的原因。
   5. 执行者已取得该 Run 的图片 `observation` 时，返回非 Prompt 运行参数的保持或调整意见及具体理由。

2. 存在多个 Run 时，执行者在各项结果后补充共同问题与差异。
