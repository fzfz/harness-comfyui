# 生产会话生成入口的根因调查

## 1. 调查结论

1. 0.48.0 已提供文件提交能力。该版本同时向模型暴露内联生成工具。模型使用内联工具，并将该工具理解为 persona 要求的受管 CLI。文件提交能力未进入实际调用路径。
2. 模型使用的取图接口同时返回完整提示词，却省略 Run 的执行状态和失败原因。模型先查询远端历史，随后直接查询本地数据库。日志分别记录了诊断任务状态和减少长文本输出的目的。
3. 批量重渲时，模型从远端历史提取 Workflow，并直接通过 HTTP 提交生成请求。这些请求绕过 Run 接纳与媒体持久化，造成会话媒体缺失。
4. 工程问题集中在生成入口、Skill 产物交接和异步查询合同。0.48.0 的文件 CLI 未进入事发会话的生成流程。调用轨迹记录了模型的绕行过程；各项接口缺陷对模型决定的影响仍需分别验证。

## 4. 文件提交和状态查询的对照验证

1. [验证脚本](../verification/generation-batch-20261028/root-cause-probe.mts)调用生产备份中的 0.48.0 CLI。Host 使用临时数据库与本地替身服务。参与验证的 Runtime、路由、请求合同和 CLI 源码与 `v0.48.0` 一致。
2. [验证结果](../verification/generation-batch-20261028/root-cause-probe.json)记录以下结果。脚本未向外部 ComfyUI 发送请求。

   | 验证条件 | 实际结果 | 能确定的事实 |
   | --- | --- | --- |
   | 从文件输入 3,195 字符的提示词 | 提交成功，保存正文，标准输出只含结果文件路径。 | 当时的 CLI 已支持文件提交，长提示词无需回填工具参数。 |
   | 同一调用身份重放相同请求 | 返回同一个 Run。 | 调用身份承担请求去重职责。 |
   | 同一调用身份提交不同请求 | 返回 `RUN_REQUEST_CONFLICT`。 | 在一个脚本调用中复用同一调用身份，无法创建多个独立 Run。 |
   | 使用 11 个独立调用身份提交 | 保存 11 条 Run。 | 文件提交可逐张完成；批量控制仍要求多次工具调用。 |
   | 同一 Run 依次进入准备完成、排队、运行和失败状态 | 取图结果在四种状态下完全相同。 | 模型无法仅凭该结果决定继续等待还是处理失败。 |

3. 四种状态的取图结果都包含 `lookup_status: available` 和空 `images`。失败状态下，Runtime 保存的错误仍未出现在该结果中。投影入口为 [readGenerationRunMedia()](../../src/host/generation/generation-runtime.ts#L813)。
4. CLI 将查询结果保存到文件。调用者可以只读取需要的字段。因此，取图时将全部提示词送回模型上下文，也与模型持续使用内联工具有关。

## 5. Skill 交接的合同缺口

1. MOSS Skill 的 Caption 草稿只有 `caption` 属性，编译结果为纯文本。该合同见会话事件 13，以及 [MOSS Skill](../../.agents/skills/moss-prompt-builder/SKILL.md)。
2. [生成 Skill](../../.agents/skills/comfyui-generate/SKILL.md)要求当前消息包含 Prompt Builder 结果 JSON。生成 Skill 使用[结果 Schema](../../.agents/skills/comfyui-generate/references/prompt-result-schema.json)校验 10 个必填属性，并拒绝额外属性。
3. MOSS 草稿缺少这 10 个属性，并多出 `caption`。编译后的纯文本也不满足对象类型要求。两项 Skill 没有定义从文件产物构造生成输入的交接步骤。
4. 当前生成 Skill 在消息缺少结果 JSON 时，会等待用户提供输入。因此，生成 Skill 无法直接承接本任务的文件产物。合同对照确认了这一交接缺口。事发模型未读取生成 Skill，其等待输入流程未在本次会话中触发。

## 6. 根因判断与替代解释

1. **入口迁移未完成。** 0.48.0 的 persona 指向 CLI，实际工具列表继续提供内联生成入口。CLI 的具体调用方式留在生成 Skill 参考中。模型直接使用可见工具，并在事件 1499 将该工具理解为 CLI。版本文件与调用轨迹共同支持这一判断。
2. **Run 的异步状态未交付给 Agent。** Runtime 保存状态和错误，取图接口只投影参数与图片。对照验证确认这一信息损失。MCP 队列提供实例范围状态，但缺少 Run 与远端任务的直接对应关系及终态错误。
3. **内联生成与取图工具要求模型重复处理长提示词。** 文件 CLI 可以减少这种文本传递，但事发模型未调用文件 CLI。事件 619 和 1499 分别记录了模型为减少查询输出和提交参数而绕行的决定。
4. **读取生成 Skill 仍不足以完成现有任务。** 第 5 节的产物合同缺口，以及第 4 节的批量限制，说明仅调整入口说明仍有执行障碍。两项属于已验证的能力缺口，其对本次模型决策的影响尚未通过对照确定。
5. **文件提交能力缺失已被排除。** 事发发布包通过了文件输入验证。实际问题包括能力发现与业务交接。
6. **CLI 冲突触发本次绕行已被排除。** 日志中没有对应调用或错误。该限制影响候选批量方案，不能单独解释历史事故。
7. **首个 HTTP 批次的会话媒体记录缺失可由 Run 登记缺失解释。** 11 项 HTTP 任务未创建 Run，媒体服务因而没有可投影的记录。本次调查尚未重现事发时的前端画面。历史会话界面的具体显示行为仍待验证。

## 8. 根因调查时的版本与结论边界

1. 根因调查时核对的安装版本为 0.48.1。该版本已移除 0.48.0 暴露的业务工具，并把业务 Skill 交付到插件包内。第 6 节第 1 项的入口迁移判断适用于事发版本 0.48.0。
2. 0.48.1 的生成 Skill、MOSS Skill、请求身份规则和媒体查询代码与 0.48.0 相同。生成 Skill 的文件交接缺口仍然存在。调用身份仍与 Run 一对一绑定，取图结果仍缺少执行状态和错误。
3. 本轮尚未使用同一生产模型做单变量重放。现有证据能够确定接口行为、实际绕行顺序和登记缺失机制；各项缺陷对模型选择的影响，以及单项修复是否足够，仍待对照验证。
