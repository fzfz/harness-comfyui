## 结论摘要

`dsh-routing-suite` 当前 `main` 不能作为一个整体直接安装到本项目。外部仓库的 Host 插件 `@dsh-external/dsh-super-injector` 声明的 Harness 兼容依据停留在 `0.1.0-rc.6`，并直接访问 Loader、Fiber、Client Module Registry 和 WebServer 的内部对象；本项目则精确锁定 `@deepseek-ai/dsh-*` `0.1.1-rc.2`，并要求插件只使用 Harness 的公开导出、服务与 Slot。外部插件的宽范围 peer dependency 不能证明这些内部对象在 rc.2 中仍保持相同语义。[外部 SPEC](https://github.com/yjh051108/dsh-routing-suite/blob/21a7260d961571c77a11705d2b0e6cf7015cc48b/injector/docs/SPEC.md)；[外部 Host 源码](https://github.com/yjh051108/dsh-routing-suite/blob/21a7260d961571c77a11705d2b0e6cf7015cc48b/injector/src/index.ts)；[本项目 Harness 锁定](/Volumes/4Tdisk/work/AI2/harness-comfyui/package.json:37)；[本项目 Harness 边界 ADR](/Volumes/4Tdisk/work/AI2/harness-comfyui/docs/adr/0012-harness-core-is-immutable.md:5)

两部分必须分开判断：

- `router-standard` Agent Preset 使用 rc.2 已提供的用户 Preset 发现机制，完成路径和组合文件适配后可以被 Harness 加载。它在阶段 0 至阶段 2 对 Tool 执行 allowlist 限制，`generate_with_comfyui` 不在列表中；进入阶段 3 后 `restrict` 被释放，全量 Tool 包括 `generate_with_comfyui` 均可见。因此，“最终阶段才调用 Generation Tool”的预期流程与 Router Standard 的设计一致，这个阶段限制是使用时序约束，不是单独的兼容性故障。需要实测的边界是：用户在阶段 0 至阶段 2 直接调用 `/comfyui-generate` 时，本项目 Skill 合同要求 Agent 在同一轮调用 Generation Tool，但该 Tool 当时不可见。[阶段表与全局 allowlist](https://github.com/yjh051108/dsh-routing-suite/blob/21a7260d961571c77a11705d2b0e6cf7015cc48b/preset/router-standard/router-bootstrap-v34.mjs#L83-L105)；[阶段 3 释放 restrict](https://github.com/yjh051108/dsh-routing-suite/blob/21a7260d961571c77a11705d2b0e6cf7015cc48b/preset/router-standard/router-bootstrap-v34.mjs#L569-L582)；[本项目 Generation Tool 合同](/Volumes/4Tdisk/work/AI2/harness-comfyui/src/host/generation/generation-tool.ts:20)
- `router-spec` 会在首个模型请求中把 Tool 过滤为 shell 加少量核心 Tool；它定义的核心集合没有 `generate_with_comfyui`。发生至少一次 durable `tool/call` 后，它才停止首请求过滤并恢复全量 Tool。这也是使用时序约束，必须与最终采用的 Router 变体一起测试。[Router Spec 核心集合与 durable Tool call 条件](https://github.com/yjh051108/dsh-routing-suite/blob/21a7260d961571c77a11705d2b0e6cf7015cc48b/preset/router-spec/router-bootstrap.mjs#L51-L72)；[Router Spec 首请求过滤](https://github.com/yjh051108/dsh-routing-suite/blob/21a7260d961571c77a11705d2b0e6cf7015cc48b/preset/router-spec/router-bootstrap.mjs#L145-L166)
- `dsh-super-injector` 不应直接启用。它是一个具备本地包注入、安装、卸载、构建、热重载、Profile 改写和路由清理能力的运行时管理器，不是只增加一个设置页的普通 Client 插件。启用它会扩大 Host 的写入与执行权限，并绕过本项目当前“源码仓库拥有 bundle composition、每次启动重新物化 Profile”的边界。[外部 Injector 源码](https://github.com/yjh051108/dsh-routing-suite/blob/21a7260d961571c77a11705d2b0e6cf7015cc48b/injector/src/index.ts)；[本项目 bundle 所有权 ADR](/Volumes/4Tdisk/work/AI2/harness-comfyui/docs/adr/0004-current-repository-owns-the-harness-bundle.md:5)；[本项目 Profile 物化代码](/Volumes/4Tdisk/work/AI2/harness-comfyui/scripts/profile/source.mjs:28)

外部仓库当前 `main` 也不是稳定发布基线。根仓库只有一个旧的 `v0.1.0` Release，该 Release 描述的是旧 submodule 布局；当前扁平化文档明确写明 router-standard 仍是研发线，不应基于该分支发布，且 CI workflow 尚未进入仓库。[根仓库 v0.1.0 Release](https://github.com/yjh051108/dsh-routing-suite/releases/tag/v0.1.0)；[扁平化迁移文档](https://github.com/yjh051108/dsh-routing-suite/blob/21a7260d961571c77a11705d2b0e6cf7015cc48b/docs/FLATTEN-MIGRATION.md)；[当前基线提交](https://github.com/yjh051108/dsh-routing-suite/commit/21a7260d961571c77a11705d2b0e6cf7015cc48b)
