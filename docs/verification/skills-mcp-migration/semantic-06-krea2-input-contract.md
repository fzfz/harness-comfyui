# Krea2 动漫 Prompt 输入契约

## 输入来源

1. 当前用户消息由普通文字和零个或多个 `type=comfyui-context` JSON 行组成。Skill 执行者将这些 JSON 行以外的文字作为本次自然语言要求。
2. Character 上下文记录是 `data.kind=character` 的 `comfyui-context` 记录；Style 上下文记录是 `data.kind=style` 的 `comfyui-context` 记录。Skill 执行者只采用这两类上下文记录。
3. 历史 Generation Run 查询结果是 Skill 执行者按照 [Generation Run 查询说明](generation-cli.md) 查询得到的结果。
4. 语义查询结果是 Skill 执行者按照 [目录查询步骤](../SKILL.md#查询目录中的作品角色画师和-prompt-词条)，根据用户消息中的查询目标进行语义查询后取得的目录记录。

## Character 上下文记录字段

1. `data.id` 为字符串，用于标识 Character。Skill 执行者可以在角色目录精确查询中使用该 ID；禁止将该 ID 写入 Prompt。
2. `data.work_name` 为字符串，用于识别角色所属作品并构造角色目录查询；禁止将该字段写入 Prompt。
3. `data.character_name` 为字符串，用于识别角色并构造角色目录查询；禁止用该字段代替 `data.prompt_text`。
4. `data.prompt_text` 为字符串或缺失，提供角色身份、外观、服装或触发词的 Prompt 来源。

## Style 上下文记录字段

1. `data.id` 为字符串，用于标识 Style。Skill 执行者可以在 Style 目录精确查询中使用该 ID；禁止将该 ID 写入 Prompt。
2. `data.name` 为字符串，用于识别画师或画风并构造 Style 目录查询；禁止用该字段代替 `data.prompt_text`。
3. `data.prompt_text` 为字符串或缺失，提供画师、媒介、线条、上色或视觉风格的 Prompt 来源。

## 读取、采用和冲突处理顺序

1. Skill 执行者先读取当前用户消息中的全部普通文字，再按照消息中的出现顺序读取全部 Character 和 Style 上下文记录。
2. 普通文字明确要求查询历史 Generation Run 时，Skill 执行者按照 Generation Run 查询说明查询指定的 `run_id`。只有普通文字明确要求采用某个查询结果中的历史正向 Prompt 时，Skill 执行者才按照查询结果的 `runs[]` 顺序读取对应的 `arguments.parameters.positive_prompt` 并采用其中的内容。
3. Skill 执行者按以下规则取得每条上下文记录的 Prompt 内容。
   1. `data.prompt_text` 删除首尾空白后非空时，Skill 执行者直接采用其中的内容。
   2. `data.prompt_text` 缺失或删除首尾空白后为空时，Skill 执行者按照目录查询步骤，使用 Character 记录的 ID、角色名称和所属作品查询角色记录，或使用 Style 记录的 ID 和名称查询 Style 记录；随后从 MCP 查询结果中采用对应的角色或画师 Prompt。
4. 内容冲突时，Skill 执行者按照 [来源优先级](../SKILL.md#构建单条-krea2-动漫-prompt) 选择内容。
5. 同一优先级的内容互相冲突时，Skill 执行者按照以下顺序保留先出现的内容；保留的内容必须符合所有更高优先级来源。
   1. 多个历史正向 Prompt 按查询结果的 `runs[]` 顺序处理。
   2. 多个 Character 或 Style 上下文记录产生的内容按记录在当前用户消息中的顺序处理。
   3. 多个语义查询结果产生的内容按查询目标在当前用户消息中的首次出现顺序处理。
6. 普通文字没有指定某项画面内容时，Skill 执行者使用优先级较低来源中的非冲突内容补齐该项。

## 完成条件

1. Skill 执行者完成“读取、采用和冲突处理顺序”中的适用步骤后，当前消息的输入处理完成。
2. 普通文字没有具体画面要求，并且所有已采用来源都没有产生可用的正向 Prompt 内容时，Skill 执行者必须请用户提供具体画面要求，然后停止 Prompt 构建。
