3. 将第 29—47 行移到“固定顺序和唯一职责”之前，并完整替换为：

   ```markdown

   2. “已采用 Character Prompt 来源”指 Skill 执行者为角色选定的用户消息、Character 上下文记录、历史 Generation Run 输入或 MCP 角色查询结果；“已采用 Character Prompt 内容”指从该来源取得并采用的完整角色 Prompt 文本。
   ```

### 3. 按提示词内容划分用户要求，避免排除整条用户消息

1. 位置：第 68、91 行，与第 33、38、42、47 行共同构成问题。
2. 独立理解及理由：文档把完整“用户消息”定义成一种已采用来源，却要求处理“不属于”该来源的用户要求。当同一条消息同时提供角色 Prompt 和额外动作、服装或场景要求时，后者也属于这条来源消息，执行者可能将其全部排除。内容选择应当区分已采用的 Prompt 文本与消息中其余要求。
3. 第 68 行完整替换为：

   ```markdown
   2. Skill 执行者将当前用户消息中已保留、且位于已采用 Character Prompt 内容和已采用 Style Prompt 内容之外的画面要求，以及已采用目录词条的规范标签，按照“固定顺序和唯一职责”表加入对应位置。
   ```

4. 第 91 行的完整替换文字见第 6 项，替换后的覆盖规则保留这一划分。

### 4. 对象颜色规则不得重新写入已经被替换的颜色

1. 位置：第 53、83 行。
2. 独立理解及理由：第 53 行要求删除冲突标签，并将替换内容写入对应位置；第 83 行却将“因用户替换要求而从该 Prompt 删除的对象固有颜色”列为应进入对应位置的内容。例如用户将角色的红发换成蓝发，第 83 行按字面要求把已删除的红色重新写入 `appearance`，使两种颜色同时存在。
3. 第 83 行完整替换为：

   ```markdown
   5. Skill 执行者将本轮 Character Prompt 之外需要表达的对象固有颜色写入对象所属位置：头发、眼睛和肤色写入 `appearance`，服装颜色写入 `outfit`，环境对象颜色写入 `environment`。用户要求替换对象固有颜色时，Skill 执行者按照“Character 来源内容”处理，并将用户要求的替换颜色写入对应位置。Skill 执行者将光源颜色、色温、光照造成的染色、阴影、亮度和对比度写入 `lighting`，将整体调色写入 `detail_mood`。
   ```

### 5. 边界章节保留归类判据和实例，删除重复职责及重复关系选择规则

2. 独立理解及理由：该节的实例能够帮助执行者区分位置，但多个条目先重新定义表格中已有的职责。第 85 行再次说明第 67、70 行的位置选择逻辑，以及第 59 行的关系内容重述例外。删除这些重复说明并保留边界判据，不会减少可执行信息。
3. 第 79—82 行完整替换为：

   ```markdown
   1. Skill 执行者将由情绪或刺激引发的脸红、流汗和其他身体反应写入 `expression_reaction`，将主体主动完成的姿态或动作写入 `action`，将穿着状态写入 `outfit`。
   2. 对后仰、退缩、颤抖或身体僵硬，Skill 执行者根据描述确定位置：描述明确表达身体反应时，写入 `expression_reaction`；描述仅表达姿态或运动时，写入 `action`。同一含义只写入一个位置。
   3. Skill 执行者将 `background blur`、`shallow depth of field` 等景深效果写入 `camera_composition`。
   4. Skill 执行者将 `watercolor paper texture`、`visible canvas texture`、`film grain`、`color grading`、`motion blur`、`speed lines`，以及残影、飞散碎屑和冲击波的提示词写入 `detail_mood`。
   ```
