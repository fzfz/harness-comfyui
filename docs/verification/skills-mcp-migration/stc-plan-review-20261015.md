# 迁移计划 STC 审阅

## 1. 审阅结论

1. 需修改项为长句、多动作步骤、重复边界和标题层级。当前没有需要用户补充的事实。
2. [迁移计划](../../plans/skills-mcp-migration-20261013.md)已采用下列改法。
3. 下文 G 编号引用 [STC 通用规则](/Users/fzfz/.codex/skills/stc/rules/for-all.md)，I 编号引用 [STC 指令写作规则](/Users/fzfz/.codex/skills/stc/rules/for-instruction-writing.md)。

## 2. 原句与改法

### 2.1 标题层级

1. 位置：第 5.3.1 节及同级子节。
2. 原句：“### 5.3.1 词条回退与格式示例的引用一致性”。
3. 问题：标题层级与节号不一致，子节显示为父节的同级。
4. 改法：按节号设置标题层级。第 5.3.1 节使用四级标题，四段编号使用五级标题。（G21、I6）

### 2.2 执行步骤

1. 位置：第 5.9 节第 3 项。
2. 原句：“再按第 5.13 节准备场景配置和可预先取得的输入，运行 `pnpm test:desktop` 构建和安装候选包”。
3. 问题：准备、构建、启动和执行连续放在一段，容易遗漏操作。
4. 改法：拆成有序步骤。先准备输入并启动应用，再选择预设和取得运行产物。（G9、I3）

### 2.3 指令强度

1. 位置：第 5.13.3.1 节第 2 项。
2. 原句：“禁止新增应用启动器、插件安装器、场景调度器、Profile 备份恢复平台，以及为每个场景编写独立执行脚本。”
3. 问题：指令强度词不统一，并列对象过长。
4. 改法：改用“不得”，按执行设施分项。保留全部限制对象。（I1、G9、G14）

### 2.4 修改边界

1. 位置：第 5.3、5.4、5.5 和 5.6 节。
2. 原句：“下列替换以外的修改仅按第 5.11 至第 5.14 节处理，其他文字保持原文。”
3. 问题：同一边界重复定义 4 次。
4. 改法：在第 5 节统一定义，各步骤只保留所属 Skill 的相对路径。（I7）

### 2.5 执行主体

1. 位置：第 5.7.3 节第 1 项。
2. 原句：“计划编写者依据……将结果文件的创建、写入和路径发布统一归属受管 CLI。”
3. 问题：实施步骤混入计划编写者的动作。
4. 改法：直接规定受管 CLI 的职责，并引用结果保存合同。（I4、I5）

### 2.6 范围引用

1. 位置：第 5.14 节第 5 项。
2. 原句：“必须执行第 8 节范围外操作才能继续时”。
3. 问题：第 8 节已列出范围外操作，原句可能被理解为相反含义。
4. 改法：改为“必须执行第 8 节列出的操作才能继续时”。（G16、I6）

### 2.7 验收和取证清单

1. 位置：第 5.3 至第 5.6 节验收项、第 5.11 和第 5.13 节。
2. 原句：“实施者保存任务输入、候选源码与安装文件身份、预设及覆盖配置、Provider／模型／推理设置、目录或夹具数据来源、主子 Session、Workspace、超时及调用上限。”
3. 问题：单句包含多组对象，执行者难以逐项核对。
4. 改法：按记录类型分项，验收任务也改为有序列表。保留失败条件、权限和不确定性。（G9、G14、G15）

## 3. 验证记录
