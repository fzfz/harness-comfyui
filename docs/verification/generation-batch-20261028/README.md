# 文件批量生成验收

## 1. 当前结论

1. [实施方案](../../plans/generation-batch-20261028.md)第 5 节的插件改动已完成。文件批量提交、请求重放、单项重做和默认轻量查询已接入现有生成服务。
2. 真实 ComfyUI 验收完成批量生成、原请求重放和单项重做。12 张图片全部进入所属会话媒体面板，重启后仍可查看，见第 5 节。
3. 自动化检查的未通过项见第 6.1 节。受控模型验收中，额外要求的 Goal 暂停操作失败，见第 6.2 节。

## 2. 版本与模型

1. 对照基线为 `0.49.0`，提交为 `c23129b5b51906015a8fd6c6fc7f6110cbe690a7`。官方 Desktop 版本为 `0.2.1-rc.3`。
2. 模型验收使用内网 `lan-gpt` 提供的 `gpt-6.1-terra`，推理强度为 `high`。请求地址为 `http://192.168.110.16:8317/v1`。
3. 模型会话使用独立官方 Profile 和工作目录。最终模型验收使用的插件包与完整质量检查构建包的 203 个文件逐字节相同，见[候选包核对记录](final-candidate-byte-comparison.json)。

## 3. 自动化检查

1. 最后一次完整质量检查通过 1,976 项非 Desktop 测试。Desktop 测试通过 307 项，失败 1 项，具体失败见第 6.1 节。
2. 类型检查通过。依赖审计的严重、高、中、低风险计数均为零。
3. [检查汇总](implementation-checks.json)记录定向测试、覆盖率与完整质量检查结果。[完整日志](quality-final.txt)保留各套件输出。

## 4. 受控模型与单变量对照

### 4.1 基线与最终候选

1. 两组均使用同一模型配置、11 份原文文件和可解码的 512 × 512 测试图。每组覆盖 5 类场景，每类运行 3 次。
2. 在[基线的 15 次执行](baseline512-model-assessment.json)中，模型均要求补充统一结果 JSON。新增 Run 和图片均为零。
3. [最终候选 15 项](candidate-final-assessment.json)的初次执行均完成生成与交付。18 次等待或已有 Run 查询输出的提示词正文字符数均为零。Goal 场景通过 2 次，另 1 次在暂停环节失败，恢复阶段未执行。
4. [产物核对](candidate-final-artifact-checks.json)完成 187 次图片读取，均可完整解码且尺寸符合要求。其中，2 次恢复执行共重复读取了 22 张图片。190 次提示词比较均与原文件一致，包含这 22 次恢复核对及 3 条预置失败 Run 的提示词。
5. 产物核对报告中的 1 个待核对阶段，对应 Goal 暂停失败后的恢复阶段。

### 4.2 单变量对照结论

1. 恢复统一结果 JSON 准入规则后，3 次文本文件任务均停在提交前。这组对照支持移除该准入限制。
2. 将提交上限改为 1 项后，模型在 1 次 shell 调用中执行 11 次受管 CLI 提交。3 次任务均完成，未观察到 HTTP 绕行。
3. 查询结果缺少状态和执行错误时，3 次任务均无法确认当前状态。查询结果包含这两项信息时，3 次任务均确认失败状态。
4. 恢复基线入口指引后，3 次任务均完成。任务已直接提供 Skill 路径，因此这组结果只覆盖已知入口的情况。
5. 各组轨迹、计数和结论适用范围见[单变量对照审阅](ablation-model-assessment.json)。

## 5. 真实 ComfyUI 验收

1. 当前真实生成采用模板 45、模型 18、实例 2。尺寸为 896 × 1344，模板原图和内置 LoRA 保持原值，额外目录 LoRA 为空。输入见[执行记录](real-comfy-final/execution-input.json)。
2. 首次批量生成完成 11 个 Run。原清单重放返回全部原 Run，新增数为 0。第 1 项使用新请求标识和 Seed 重做后，新增 1 个 Run，总数为 12。
3. [产物核对](real-comfy-final/artifact-checks.json)确认 12 张图片均可完整解码，尺寸均为 896 × 1344。保存的正向提示词与原文件一致，其他参数符合清单。API Workflow 和 Actual Workflow 均与远端历史一致。本地图片字节与远端图片一致。
4. [生命周期与界面核对](real-comfy-final/lifecycle-and-ui-checks.json)确认原 Run 和媒体保持不变。重启前后，所属会话面板均显示 12 个 Run 和 12 个媒体；3 页中的全部图片均加载成功。界面见[重启后截图](real-comfy-final/after-restart-page-1.png)。
5. [模型执行审阅](real-comfy-final/model-assessment.json)确认 3 个回合均使用指定模型。等待查询输出的提示词正文字符数为零；交付包含完整 Run ID 和图片路径。
6. [清理记录](cleanup-checks.json)确认测试实例端口已释放。独立 Profile、工作目录和图片均已保留。

## 6. 自动化失败与额外测试条件

### 6.1 已结束子会话的 Skill 目录

1. 已结束子会话保留工作台 preset，但 `remote.skills.list` 返回 7 个 Office Skill。测试预期为 8 个项目 Skill。
2. 宿主只为存活 Agent 选择 preset 的 Skill 服务。已结束会话使用全局 Skill 服务；preset 租约只提供作用域标识。
3. 源码位置和实际调用证据见[Skill 目录失败记录](official-cold-skill-failure.json)。修复责任位于宿主会话 Skill 服务解析。

### 6.2 Goal 恢复测试的暂停失败

1. 验收任务要求测试模型在第一阶段完成后暂停 Goal。子会话完成 11 张图片后，主会话在接收子会话通知的回合中调用 Goal 暂停接口，宿主拒绝了该操作。
2. 宿主要求暂停操作所在回合包含直接用户消息。提交验收任务的回合已经结束，后续通知回合和自动 Goal 回合均不含直接用户消息。
3. Goal 随后进入阻塞状态，恢复阶段未执行。完整事件和源码见[Goal 暂停失败记录](official-goal-pause-failure.json)及[宿主授权源码摘录](official-goal-pause-source.json)。
4. 此项记录为额外测试条件的失败。本次插件验收目标见实施方案第 7.1.8 项。

## 7. 证据边界

1. 初期 1 × 1 测试图无法完整解码，其模型结果不计入业务通过数。[初期审阅](candidate-invalid-fixture-assessment.json)保留失败证据；第 4 节汇总使用 512 × 512 测试图重新验收的结果。
2. 原始模型请求与原始流未由官方应用持久化。各导出索引记录 `RAW_MODEL_REQUEST_NOT_PERSISTED` 和 `RAW_MODEL_STREAM_NOT_PERSISTED`。模型行为结论依据已保存的会话事件与工具结果。
3. 固定测试图片覆盖提交、登记、参数、文件和媒体显示。真实生成的参数与产物核对见第 5 节。
