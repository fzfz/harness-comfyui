# H7 任务委派与图像验收修复方案

## 1. 名词定义

1. H7：宿主升级方案中的真实模型与 Skills 验收项，定义见[升级方案第 7 节](host-0.2.1-rc.2-upgrade-20261024.md#7-计划验收清单)。
2. 委派任务：主 Agent 已通过派发工具交给指定子会话执行的工作，包含输入、输出文件和完成条件。
3. 接纳回执：宿主已经接受任务的身份记录。完成通知：宿主报告该次执行结束的消息。
4. 独立观察：观察 Agent 根据图片描述可见事实。目标比较：比较 Agent 根据这些事实逐项判断用户要求。
5. 实施者：批准方案后修改插件和 Skill 的开发 Agent。验收者：执行官方 Desktop 验收并核对原始证据的 Agent。独立 Reviewer：使用干净上下文审阅指定材料的队员。

## 2. 总目标

1. 同一委派任务由指定子会话执行。主 Agent 负责派发、接收、核对和交付。
2. 生成任务因输出上限中断后，主 Agent 核对已有产物，并向原生成子会话续派任务。
3. 每张图片分别满足全部必要条件，才可判定目标达成。缺失或冲突的观察须得到补充，或保留为无法确定。
4. 修复对象为独立 worktree 中的插件 `0.47.0` 候选，宿主基线保持 `0.2.1-rc.2`。

## 3. 现状调研

1. 调查从官方 Session 导出、实际工具参数和返回值开始。图片判断同时核对原图、观察原文与比较产物。
2. 当前调查覆盖任务输入、首次规则读取、首次偏离及后续影响。调查使用 Session 序号串联事件，并核对源码与宿主公共接口。
3. 当前证据保存连续会话事件。原始 Provider 请求和响应流未完整持久化。缺失范围由各 `trace-index.json` 标记。

## 4. 面临的问题

1. 委派后的执行归属失守。主 Agent 在接纳后继续写入子任务产物，又执行生成步骤。现有工具说明主要约束后续依赖任务，未形成明确的委派后工作交接。
2. 执行结束原因被用于推断会话失效。主 Agent 已读到续派要求，仍把输出上限解释为需要新建会话。当前派发参数使这个选择直接进入创建分支。
3. 观察与目标比较发生信息混用。第一轮观察收到期望画面的问题，比较阶段又用复合要求中的一个条件代表整项要求。
4. 观察矛盾未阻止达成判定。比较 Agent 处理了持伞描述的矛盾，却遗漏空间关系的矛盾。
5. 当前已确认动作、输入和结果的关系。诱导式问题、参考漏读和接纳提示各自的影响尚待对照验证。方案按第 5.2 节选择有证据支持的修改。

## 5. 问题的解决和实施方案

### 5.1 架构与职责

1. 插件提供任务参数和接纳身份。角色 Preset 定义职责，Skill 定义业务步骤。宿主管理子会话生命周期。观察和比较 Agent 负责语义判断。

   ```mermaid
   flowchart TD
     U[用户要求] --> M[主 Agent 分配输入、输出和执行者]
     M --> D[派发适配器提交任务]
     D --> H[宿主创建或续派子会话并返回接纳身份]
     H --> G[生成子会话写入 Builder 并提交 Run]
     G --> N[宿主结束通知]
     N --> R[主 Agent 读取结果并核对 Run]
     R --> O[观察 Agent 先描述可见事实]
     O --> C[比较 Agent 逐项核对必要条件]
     C -->|证据缺失或冲突| O
     C -->|Prompt 需要修正| G
     C -->|同一图片全部满足| F[主 Agent 核对证据并交付]
   ```

2. Goal、Shell、Skill、Workspace 和宿主原生子会话能力继续保留。工作台仍可直接执行用户交给主 Agent 的任务。
3. 程序只校验参数、身份、路径和数据结构。图像关系、证据含义与达成判断由 Agent 审阅。

### 5.2 步骤一：补齐单变量对照

1. 实施者固定每组实验中除表列变化项以外的条件，包括候选包、模型、模型参数与任务输入。每个实验使用独立任务目录，保留全部运行结果。
2. 验收者按下表分别执行基线和候选条件。每个条件重复 `3` 次；该次数用于本轮回归观察，不代表统计可靠性保证。

   | 实验 | 固定项 | 唯一变化 | 判断依据 |
   |---|---|---|---|
   | 委派归属 | Builder 输入、同一模型、延迟返回的子任务 | 接纳时提供明确执行者与交接动作 | 主 Agent 是否再次写入指定子任务文件或执行相同工作 |
   | 输出上限恢复 | 原生成子会话、已有产物、宿主版本 | 使用原 `agent_id` 续派 | 子会话 ID、下一条接纳消息及实际完成结果 |
   | 首轮观察 | 现有原图、视觉模型与采样参数 | 原问题与中性描述要求 | 独立 Reviewer 对空间、动作和矛盾的逐项判断 |
   | 比较参考读取 | 同一构图、用户要求、原始观察与输出格式 | 明确执行比较参考的读取步骤 | 参考是否读取，空间矛盾是否影响达成判断 |
   | 比较完整性 | 同一构图、用户要求、原始观察与已读取参考 | 逐项证据表 | 是否分别判断人物数量、站立位置、持伞关系等条件 |

3. 委派对照先使用文件任务和受控生成服务。视觉对照复用现有图片。对照结论成立后，再完成第 7 节的真实 Run 验收。
4. 当前模型可用且免费时，实验沿用原模型。模型不可用时，验收者记录替代模型，并重新执行两组条件。
5. 某候选修改未改变目标行为时，实施者保留失败记录，继续定位首个偏离。超出本方案职责范围的改动须形成补充方案。

### 5.3 步骤二：明确委派后的执行归属

1. 实施者将共同委派合同集中到派发适配器的一份模型可见说明中。各产品 Preset 只保留角色与业务差异。
2. 委派合同要求主 Agent 在派发前确定子任务的输入、输出文件和完成条件。接纳后，指定子会话负责该工作及其产物。
3. 主 Agent 在接纳后保存身份，并等待宿主完成通知。主 Agent 可处理与该子任务无关的工作。主 Agent 不得代写该子任务文件或重复提交该子任务的图片。
4. 子任务存在缺项时，主 Agent 向原先接纳任务的子会话补充材料。主 Agent 取得结果后读取和核对产物，再派发后续任务。
5. 接纳回执统一提供 `status`、`operation`、`subagentId` 和 `messageId`。`operation` 区分创建与续派。工具返回和附加上下文由同一个回执对象派生。
6. `task.md` 保存该回执及结果文件路径。宿主记录是会话身份与运行状态的来源，任务文档用于业务交接。
7. 实施者修改 `project-iteration-dispatch.mjs`、两个产品 Preset 的派发声明及对应合同测试。回执结构集中定义，各工具复用。

### 5.4 步骤三：在原生成子会话中恢复任务

1. 实施者在迭代 Skill 的续派步骤中定义输出上限恢复。收到 `max-tokens` 通知后，主 Agent 读取该子任务已有文件和 Run 记录。
2. 原会话身份可用时，主 Agent 使用原角色工具和原 `agent_id` 续派。身份缺失时，主 Agent 先通过 `list_agents` 找回。
3. 已有 Run 时，生成 Agent 先查询状态和媒体。尚未提交时，生成 Agent 从已有 Builder 或输入继续。生成数量按整个任务累计。
4. 宿主拒绝续派时，派发工具保留原错误和会话 ID。主 Agent 根据该错误处理缺失条件。输出上限本身不构成新建会话的条件。
5. 实施者修改迭代 `SKILL.md` 的恢复分支及 `records.md` 的交接字段说明。角色 persona 引用该步骤，删除重复的恢复解释。
6. 验收覆盖正常续派、输出上限和重启后的续派。另测消息接纳后父任务中断与无效会话身份。

### 5.5 步骤四：分离独立观察与目标比较

1. 首轮观察只接收实际图片引用、输出路径和通用观察要求。通用要求覆盖人物、动作、接触关系、空间关系、环境与无法辨认之处。
2. 主 Agent 将原始故事、构图目标和期望答案交给比较 Agent。观察 Agent 先写原始可见事实，再由比较 Agent 判断目标。
3. 首轮观察采用第 1 项的固定要求。补充观察由比较 Agent 指出缺少的事实，观察 Agent 将其写成中性问题后交给视觉模型。例如：“人物脚下是什么表面？该表面与桥面、桥拱的位置关系是什么？”
4. 观察 Agent 保存视觉模型返回原文。存在相互冲突的描述时，观察 Agent 保留冲突，比较 Agent 将对应条件标为无法确定。
5. 比较 Agent 首先读取比较参考、用户要求、构图文件与观察文件。比较 Agent 把每个复合要求拆成可独立判断的必要条件。
6. 比较结果按同一图片逐项保存要求原文、必要条件和可见证据。每项结论为满足、不满足或无法确定，并记录待补充的事实。比较 Agent 为每个必要条件分别给出能支持该结论的证据。
7. 任一必要条件不满足时，比较 Agent 提出修正方向。任一条件无法确定时，主 Agent 补充观察，或在停止时交付未达成说明。
8. 比较 Agent 判定可见偏差后，再读取 Prompt、参数与历史结果分析原因。主 Agent 交付前核对逐项结果、原始观察及同一媒体身份。
9. 实施者修改观察派发参数、观察与比较角色、迭代 Skill 及 `iteration-method.md`。首轮与补充观察的输入结构明确区分，参数校验只检查结构。

### 5.6 步骤五：审查与交付

1. 实施者先为回执与参数合同编写失败测试，再修改代码。语义流程通过干净上下文执行验证。
2. 独立队员在指定工作目录执行指定 Skill 和任务参数。实施者观察其调用轨迹与产物，执行期间不追加提示。
3. 独立 Reviewer 按文件完成语义审查。代码审查覆盖接口合同、数据来源及可删除的重复代码。
4. 最终候选依次通过 `pnpm quality` 和 `git diff --check`。验收者执行第 7 节真实模型矩阵，并保存对应版本与完整事件索引。
5. 验收者停止本轮官方 Desktop，核对进程与端口释放。worktree 专属 Profile、Workspace 和业务数据继续保留。

## 7. 计划验收清单

1. 验收者逐项核对下表，并保存成功和失败运行。每项真实场景连续执行 `3` 次；任一次失败均保留该项未通过状态。

   | 编号 | 场景 | 通过条件 |
   |---|---|---|
   | A1 | 工作台委派 Builder | 指定子会话独立写入结果；主 Agent 收到完成通知后读取结果 |
   | A2 | 工作台委派一张图片 | 父会话提交数为 `0`；子会话产生 `1` 个 Run；ComfyUI 对应 `1` 次执行 |
   | A3 | 子会话输出上限 | 后续消息进入原生成 Session；已完成步骤与已有 Run 得到复用 |
   | A4 | 父任务中断、应用重启，分别验收 | 两种场景均能找回原先接纳任务的子会话并续派；接纳身份与原生事件一致 |
   | A5 | 桥下原图 | “站在桥上”判为不满足；证据明确说明脚下承托面和桥的相对位置 |
   | A6 | 关系类同类场景 | 人物在物体前后、手与物件接触、多人数量等条件分别判断；证据不足时保留无法确定 |
   | A7 | 正确图片与模糊图片 | 正确图片可通过；遮挡或不可辨认内容不会被推断为满足 |
   | A8 | 完整迭代 | 原生成子会话接收比较反馈并再次生成；观察、比较使用本轮正确媒体；累计张数符合用户限制 |
   | A9 | 业务结果与生命周期 | task.md、接纳身份、完成通知、Run 与媒体对应；进程和端口释放 |
   | A10 | 最终候选 | 独立审查、完整 quality 和差异检查通过；原升级 H7 的剩余 Skill 分支同时满足原验收要求 |

2. A5 至 A7 由独立 Reviewer 直接查看图片并核对逐项结论。程序只核对文件、身份、调用次数和确定性数据结构。
3. A6、A7 优先使用现有图片作为固定样本。验收者在执行前确定样本与判断依据，并保留全部样本结果。
4. 真实生成使用原升级方案获准的免费模型与 ComfyUI 环境。实施者在执行前核对模型价格，记录各角色和视觉模型配置。
