# DeepSeek Harness 0.2.1-rc.3 插件升级方案

## 1. 名词定义

1. 目标宿主：官方 macOS DeepSeek Harness Desktop `0.2.1-rc.3`。
2. 源码基点：插件 `0.47.1` 的 `main` 提交 `6adc446c78aa177dc9213fdec47a37a9441c1a05`。
3. 候选插件：本轮交付的 `harness-comfyui@0.47.2`。
4. SDK 依赖视图：独立 worktree 中供类型检查和测试使用的官方包目录。

## 2. 总目标

1. 实施者使候选插件支持目标宿主，并通过第 7 节验收。
2. 发布者创建 PR、合入 `main` 并发布同一提交的插件包。
3. 部署者通过官方 Desktop 安装 Release 附件，保留用户配置和业务数据。

## 3. 现状调研

### 3.1. 源码与接口

1. 官方目标标签比 `dsh-v0.2.1-rc.2` 增加 6 个提交。目标提交为 `1f81c047fc48fa190a683e469daa699857e9afe8`。来源见[官方发布记录](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.3)。
2. 宿主增加导航入口菜单，并调整新会话的草稿复用行为。DeepSeek API Key 适配器改用官方模型列表。
3. 子 Agent、Workspace 服务、凭据、Skill、Shell 环境和 Remote 协议的实现保持原样。插件注册的界面扩展位继续可用。逐文件差异见[源码证据](../verification/host-0.2.1-rc.3/source-baseline.json)。
4. 本机官方应用已安装目标宿主。源码基点仍声明 `0.2.1-rc.2`，Desktop 验收配置也使用该版本。

### 3.2. 安装前依赖审计

1. [依赖审计](../verification/host-0.2.1-rc.3/dependency-audit.json)记录 299 个精确包版本。插件运行与构建依赖中的 184 个版本未命中公告。SDK 与 Preset 依赖涉及以下公告。

   | 依赖版本 | 公告数量 | 公告描述的影响 | 公告列出的修复版本 |
   | --- | --- | --- | --- |
   | `@modelcontextprotocol/client@2.2.0` | 1 | 跨源重定向转发自定义请求头及请求体。 | `2.3.0` |
   | `fast-uri@3.1.8` | 4 | URI scheme、主机及相对路径的解析或规范化错误。 | `3.1.9` |
   | `undici@8.11.2` | 3 | EventSource 内存耗尽、响应编码拒绝服务及完整性校验绕过。 | `8.12.2` |
   | `zod@4.4.3` | 1 | 校验超大集合时耗尽内存。 | `4.6.6` |

2. 具体触发条件由审计文件中的公告链接说明。官方 Desktop 内各调用路径的可利用性仍待宿主维护者评估。
3. 插件直接开发依赖继续使用 `undici@8.12.2`。
4. SDK 依赖视图按[精确清单](../verification/host-0.2.1-rc.3/sdk-package.json)安装。安装关闭生命周期脚本；审计发现的安装脚本为 `fsevents@2.3.3` 的 `node-gyp rebuild`。

## 4. 面临的问题

1. 插件安装清单的宿主约束与目标宿主不同，必须同步更新 DSH peers。
2. 开发 SDK 和 Desktop 测试基线必须采用目标版本，才能验证实际接口。
3. 验收者需要通过官方界面验证导航入口可用，以及草稿的会话上下文归属正确。

## 5. 解决方案与实施步骤

### 5.1. 架构与职责

1. 插件继续通过官方公共接口接入宿主，模块职责见[系统架构](../system/architecture.md)。宿主负责 Session、Workspace、凭据、子 Agent 和原生 Goal；插件负责 ComfyUI 生成、媒体和图片读取。

   ```mermaid
   flowchart LR
     D[官方 Desktop] --> C[插件 Client]
     C --> H[插件 Host]
     P[项目 Preset 与 Skill] --> A[宿主 Agent 与子 Agent]
     A --> CLI[受管 CLI]
     CLI --> H
     H --> G[ComfyUI 与媒体存储]
     H --> I[图片读取 Provider]
   ```

2. 实施者按已确认的接口差异修改所属模块。发现接口调用失败时，先追踪参数、返回值和宿主实现，再修正对应适配。

### 5.2. 实施步骤

1. 在分支 `codex/host-0-2-1-rc-3` 更新安装包版本断言，验证当前清单无法满足目标版本。
2. 更新插件版本、`engines.dsh`、DSH peers 和 Desktop 验收配置。
3. 生成 SDK 锁文件，核对全部包版本属于审计清单。锁文件包含清单外版本时，先补充这些版本的依赖审计，再取得对应安装授权。
4. 关闭安装脚本，安装精确 SDK 依赖。
5. 运行类型检查及受影响的包合同、Preset 和子 Agent 测试。
6. 在官方 Desktop 完成第 7 节的界面与业务验收。
7. 更新 README、发布说明、技术栈和安装指南。
8. 完成独立规范审查、需求审查与文档语义审查。
9. 对最终候选树运行 `pnpm quality` 和 `git diff --check`。
10. 提交并推送候选，创建 PR 并合入 `main`。
11. 按[发布规范](../system/releasing.md)发布插件 tarball。
12. 按[安装与更新指南](../user/install-update.md)备份、安装和验证本机插件。

## 6. 方案待决策项清单

1. 当前无待决策事项。

## 7. 计划验收清单

1. 安装包、SDK 和官方应用身份符合第 1 节版本；tarball 的导出目标完整。
2. 官方插件管理器能安装并启用候选；插件设置、输入区上下文入口及媒体结果页可用。
3. 7 个项目 Preset 可见，原生 Goal 可用，项目 Skill 能从安装包读取。
4. 子 Agent 首派、续派、完成通知和取消按公共合同工作，父子 Session 归属正确。
5. 切换会话和返回未发送草稿时，Workflow 上下文与 Session 保持对应。
6. 凭据、图片读取设置和 Workspace 能读取并持久化；受管 CLI 返回可读取的结果文件。
7. 真实模型完成目录查询、ComfyUI 生成、媒体查看和图片读取。证据包含模型、Session、Tool Call、Run 和媒体路径。验收者记录模型的画面位置判断和 Prompt 语义偏差；宿主兼容性以调用成功、数据归属和产物可读取为通过条件。
8. 完整门禁通过；测试结束后，本轮进程和端口全部释放。
9. 本机安装的插件与 Release 附件一致；更新前的配置、凭据、历史 Run 和媒体保留，更新后的生图与读图调用成功。

## 8. 非本次目标

1. 官方宿主源码和安装包的依赖修复由宿主项目处理。
2. 历史环境迁移、退役或删除需要对应任务授权。
3. 其他操作系统适配和业务功能扩展属于后续任务。
