# ComfyUI 工作流设计与实测

## 1. 明确任务

1. 读取用户的实例地址、画面目标和输入文件。已有工作流须列明要改变的行为和要保留的内容；从零设计须列明输出内容、尺寸及数量。
2. 仅对影响执行的缺失信息提问。记录用户授权的实例操作和运行限制；未指定限制时，先说明预计运行次数与停止条件。
3. 保留原始工作流作为基线，将候选工作流另存为文件。不得覆盖用户原始输入、安装未经授权的依赖或插件，以及重启实例。

## 2. 读取工具与实例能力

1. 命令入口是 `scripts/comfyui.mjs`，路径相对于本 Skill 目录。首次使用时从该目录执行 `node scripts/comfyui.mjs --help`；每个命令首次调用前读取该命令的 `--help`。
2. 使用 `inspect` 保存实例版本与节点索引。先阅读索引，再按本次任务读取所选节点的完整定义。大结果从命令返回的文件路径读取。
3. 根据节点定义核对已安装模型的有效引用。模型兼容性须结合模型元数据、作者说明、安装源码或实际加载证据判断；不得仅凭文件夹名推断模型家族。

## 3. 研究节点与组合方式

1. 围绕当前任务查明节点用途、输入输出含义、参数影响及组合条件。沿“注册名称 → 安装源码 → 执行函数 → 输入来源与输出用途”读取证据。
2. 遇到动态控件、控件转输入、子图或前端专用节点时，继续读取对应前端扩展和作者示例。区分 UI Workflow 的编辑信息与 API Prompt 的执行参数，不得凭控件位置猜测参数映射。
3. 遇到图像、遮罩、批次或分支组合时，核对尺寸、数值范围和遮罩方向。区分数据列表与图像批次，并核对节点的实际执行条件。接口类型相同仍须核对数据含义。
4. 安装源码不足以解释行为时，查阅官方或插件作者的源码、文档和示例。区分已核对事实、推断及待实验确认的问题，不得把在线版本的行为直接认定为实例行为。
5. 已安装资源无法满足目标时，研究候选插件的 Git 仓库及现有节点的替代组合。列明候选版本、依赖、安装影响与待验证项，取得用户授权后才能安装插件或执行下载的代码。

## 4. 创建与导出工作流

1. 根据研究结果编辑 UI Workflow JSON。核对节点、连接、模型引用和全部目标输出；修改已有工作流时保留约定的分支、布局和参数。
2. 使用 `export` 将候选工作流交给目标实例的前端导出。检查返回的 UI Workflow JSON、API Prompt JSON 和重新导入结果，确认所选节点与参数对应用户目标。
3. 导出失败或重载后内容变化时，读取错误记录和对应节点的前端源码，修正后重新导出。不得将失败的导出记录提交运行。

## 5. 运行、观察与调优

1. 根据用户要求，从导出的 API Prompt JSON 中确定全部目标输出节点，再使用 `run` 提交配套导出文件。修改已有工作流时，先运行基线工作流，并保存所用输入和实际参数。
2. 根据命令返回的状态处理任务。等待中的任务使用 `status` 查询；提交结果未知时，必须保留记录并继续查询，不得重复提交。不得取消或中断用户其他任务。
3. 读取任务记录、节点错误及全部目标图片。程序核对数量、尺寸和确定性运算结果；直接观察主体、动作、构图、风格、文字及用户指定细节。不得以 HTTP 成功、文件存在或执行完成替代画面验收。
4. 发现偏差时，记录具体目标、实际差异和证据位置。提出可验证的原因，选择最小改动，再运行对照；保留调整前后的参数与图片。
5. 满足目标后结束调优。达到运行限制、资源缺失或需要新增授权时，交付当前结果和未满足项，不得自行降低用户目标。

## 6. 交付

1. 交付可编辑的 UI Workflow JSON、对应 API Prompt JSON、模型与节点要求、实际图片及运行记录。每张图片须能关联到实际参数和任务 ID。
2. 按用户目标列出满足、未满足及证据不足的项目，指向对应图片或记录。说明已验证的实例版本和已知限制，由用户确认画面偏好。
