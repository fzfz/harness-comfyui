# rgthree seed 与提示词画面不一致诊断计划

## 必须要实现的目标

- 计划执行者必须诊断截图对应的 Generation Run 中，Agent 展示的 Prompt、内部请求快照、Actual Workflow、API Workflow 与 ComfyUI 最终提交参数是否一致。
- 计划执行者必须找到历史提交中处理 rgthree `seed = -1` 的代码、自动化测试和适用模板结构。
- 计划执行者必须比较本次模板与历史修复覆盖的工作流结构，确认本次异常是否由相同根因触发。
- 计划执行者必须在 `.planning/diagnose-rgthree-seed-prompt-mismatch/` 目录中保存诊断复现测试，并输出含复现命令、证据、根因和建议修复范围的诊断结论。

## 验收清单

- 计划执行者必须提供一个 Agent 可运行的命令，用于确定性识别“运行记录中的请求 Prompt 与实际提交 API Workflow 的正向提示词是否一致”。
- 计划执行者编写的诊断记录必须包含截图中的 `run_id`、模板名称以及本地运行记录中的对应文件或数据库记录。
- 计划执行者编写的诊断记录必须指出历史 rgthree 修复提交及该提交覆盖的工作流节点结构。
- 计划执行者编写的诊断记录必须指出本次模板是否落入历史修复分支，并给出可证伪的根因结论。

## 非本次目标

- 计划执行者不得修改 `src/` 目录中的生产源码、`tests/` 目录中的既有自动化测试、配置、Workflow 模板或生产运行状态。
- 计划执行者不得重新提交 ComfyUI Generation Run。
- 计划执行者不得发布新版本或部署生产实例。

## 已获得的授权

- 用户已授权计划执行者只读检查当前仓库、历史提交、本地运行数据库、运行产物和截图，并在 `.planning/diagnose-rgthree-seed-prompt-mismatch/` 目录中保存和运行最小诊断复现测试。
- 用户尚未授权计划执行者修改生产源码、修改既有自动化测试、发布新版本或部署生产实例。

## 执行阶段

1. `complete`：计划执行者已建立截图运行记录的确定性一致性检查命令。
2. `complete`：计划执行者已复现并最小化本次模板中的 Prompt 映射差异。
3. `complete`：计划执行者已列出并检验 3 至 5 个可证伪根因假设。
4. `complete`：计划执行者已形成诊断结论和建议修复边界。
