## 关键问题

1. 弹窗是否在关闭时卸载，还是保留挂载但主动重置状态？
2. 四类状态当前分别归属哪个 React 模块或状态容器？
3. “上次选择”应限定在当前浏览器页面生命周期、当前会话、当前任务还是全局范围？
4. 底模变化是否会使左侧选择、搜索词或分页结果失效？
5. 现有测试使用哪个可观察接口验证弹窗恢复行为？
6. 每个 Session 的弹窗记忆是否只需跨 Session 切换保留，还是浏览器刷新或 Client 重启后也必须保留？用户已经确认浏览器刷新和 Client 重启后也必须保留。

## 已作出的决定

| 决定 | 理由 |
|---|---|
| 独立 worktree 从当前 `main` 的已提交 HEAD 创建 | 主 worktree 存在用户未提交改动，独立 worktree 可以避免覆盖或混入这些改动。 |
| 本次只产出调研记录和待批准方案 | 用户明确要求批准后才实施需求。 |
| 前端实现入口优先从 `src/client/workbench/` 调研 | `docs/system/architecture.md` 把上下文选择器归属到 `src/client/`，字符串搜索把“插入上下文”定位到 `src/client/workbench/contract.ts`。 |
| 原“只保留 `WorkbenchDock` 本地状态”的推荐已经作废 | 用户明确指出每个 Session 必须保存并恢复自己的记忆；React 实例生命周期不能表达 Session 级状态归属。 |
| 新方案必须使用 `sessionId` 隔离记忆 | `src/client/index.tsx` 的 `conversation.input.dock` 注入函数已经接收 `sessionId`，该 ID 是现有 Session seam 上可用的结构化 key。 |
| 推荐新增 Client 插件级 `ContextDialogNavigationStore` | 该 module 能以稳定 `sessionId` 隔离导航快照，并且不把 UI 状态写入 Session 草稿或依赖 React 实例复用。 |
| 推荐每个 Session 使用一个版本化 `localStorage` key | 该结构可以跨浏览器刷新和 Client 重启恢复，不引入依赖、数据库、Remote 接口、Host 合同或全局 Session 索引。 |
| Storage 更新采用同步写穿 | 新状态必须在 `setItem()` 成功后才进入内存快照，避免界面显示已保存但重启后丢失。 |
| Storage 错误进入 Session 快照并在 Modal 中显示 | 该行为避免静默降级，并让其他 Session 的导航状态保持不变。 |
